# 架构决策

## ADR-001：基准路径修复与保留（2026-11-09）

用户指定路径初始不存在。工作区唯一原件为 architecture 下 v0.2 文档，故先全文阅读，再按字节复制到约定路径；两者 SHA256 一致，原件保持不变。此文档及用户限定的 A+B 范围是本轮基准，未以其他模板替换需求。

## ADR-002：模块化单体、CLI、轻依赖

采用 Python ≥3.11、Pydantic 2、SQLAlchemy+SQLite、PyYAML、argparse；测试 pytest、ruff。本机独立环境实际为 CPython 3.14.3，尚未声明在其他 Python 版本通过验收。依赖在 pyproject 中限制主版本，uv.lock 保留本轮解析结果。pandas/pyarrow 仅为后期可选项，不安装模型/UI/设备依赖。

## ADR-003：有关系的实体 + 不可覆盖的 JSON 原始契约

SQLite 为 source/extraction/recipe/synthesis/test/observation/characterization 建独立表与外键，嵌套 Measurement/步骤用 JSON 列保留。所有已成功解析的输入行进入 staged_record 审计档案；无 block 才创建 curated_record 和领域实体。相同实体 ID 不同内容一律阻断，不执行 upsert 覆盖。真正修订需审核后使用新版本 ID，当前不提供修订向导。

选择 CSV 嵌套 JSON 单元格，而不将全部步骤和组成压成脆弱的固定元素列；CSV/JSON 共用完全相同 Pydantic 契约。单记录粒度为一个 test_run 及其 observation 列表；recipe/synthesis 在多行复用，实体 ID 相同就必须内容相同。当前每条记录引用一个 extraction_record，可在 locator 中列出组合定位、provenance 中补充分字段说明；多定位对象图导入是后续扩展。

## ADR-004：原始数值是字符串，缺失是显式状态

原值字符串保留小数格式，不从空字符串、NA、0 隐式推断未知语义。reported/zero 要求原值；未知/未报告/不适用/未测要求 null；invalid 可保留无法解析的原文。治理再用 Decimal 检查有限数值、零状态和范围。范围/约数等暂保留并阻断，不猜测代表值。

## ADR-005：单位只做有定义的局部换算

测试 T 转 K，P 仅在明确绝压时转 bar(abs)；不推断大气压力来换算表压。GHSV 记录参考温度、参考绝压和催化剂体积基准，不将不同基准的 GHSV 当作可互换值。组成百分比只检查闭合，不自动重归一；比例不当成百分数。默认闭合容差 0.5 个百分点，可配 0–5。没有统一测试工况换算，没有收率/STY派生。合成/表征未支持单位保留并 warning，不暗中换算。

## ADR-006：治理通过 ≠ 人工核验

curated 默认 pending；导入声明 verified/rejected 不被信任，产生 block 并保留原输入。审核命令只能作用于 curated，要求复核人、核对证据，并显式确认 warning。核验范围为整条记录；每次审核追加 review_event（含当时内容哈希、代码/配置元数据）。输入与历史导出保持原始 pending；有效核验状态在独立审核表，不修改抽取历史。

审核是本地操作者声明，尚无身份认证/角色隔离。软件不能证明人真的读过文献，不能用此接口替代项目核验制度。

## ADR-007：快照先冻结 JSON，保留后期接口

研究快照只允许人工核验的 research 记录，核查审核内容哈希、原始证据文件、目标存在性、标准值、定义/单位一致性；任何混合口径先拒绝。冻结包含完整实体及表征的证据包，未来特征阶段另按 A/B/C 分层构建。声明 source/recipe/synthesis 分组需求但不伪称已做切分。

快照按内容哈希命名，时间在哈希外层，相同内容幂等复用；已有文件不同内容拒绝覆盖。显式 demo 模式保留 synthetic_demo 标签、scientific_use=false，文件放在 demo 子目录，禁止研究快照混用。它只用于验证成功路径。

尚未实现 Parquet/训练表、清洗版本升级回放、模型训练、候选生成。未来模块用 Protocol 预留，不暴露会伪造结果的 train/screen 命令。

## ADR-008：4 默认、6 硬上限

配置和 ExperimentBatch 均约束容量为整数 1–6，默认 4；候选槽位数不得超过配置容量。允许小于 4 的试验计划，设备能力仍未核实；重复/对照样需单独样本 ID。CLI batch check 只是契约检查，尚不持久化真实实验计划。

## ADR-009：可追溯证据和存储边界

原文件按 SHA256 路径只追加留存；report/run/staged 关联实际 CSV 物理行范围或 JSON 索引。报告附 UTC 时间、数据/配置/代码哈希、软件与治理版本、model_run_id=null；Git 不存在时 code_revision=unversioned，不伪造 commit。运行 ID 用于区分导入事件，记录指纹用于重复检测。

SQLite 一次事务提交整次入库，允许合格行 curated、坏行 staged。文件导出在提交之后，数据库和文件系统不具备跨介质原子性；失败时可能缺导出文件或留下 raw 孤立文件，不丢弃历史输入。质量报告可从 import_run 重导出；更完整恢复工具列为待办。只读原件是应用策略，尚未做 OS 写保护或数字签名。

## ADR-010：论文建议以增量验收要求融入原路线（2026-11-09）

延续原A–F路线和模块化单体，保留现有schemas/storage/governance及实体关系；不按论文仓库或评审目录图重构。用户已明确目的为吸收有效部分。

以[实施与验收清单](implementation_amendment.md)将目标资格、分组防泄漏、设计输入准入、训练折拟合映射到B完善和C阶段；解释、适用域及推荐仍按原D/E/F推进。后续按功能需要增加datasets/features/modeling，不预建全套空模块。

兼容ADR-007：现有目标快照继续严格检查所选完整记录；新增目标资格清单在调用前显式筛选并记录排除原因，不能静默改写dataset build语义。逐观测冻结等接口若需要扩展，须另定版本和回归要求。已有Observation通过外键链追溯上游，不为满足评审措辞冗余复制字段。

上述算法与接口扩展均为规划；本次只登记实施约束和顺序，不改变运行行为或声明新增科研成果。

## ADR-011：目标资格清单位于严格快照入口之前（2026-11-09）

I1采用独立datasets模块和dataset qualify命令，显式记录全部选择、目标口径及排除原因。未审核记录可在清单中被排除，但不能被自动批准；审核拒绝/撤销和证据完整性问题阻断整次冻结，即使该记录本来就因缺目标被排除。

继续使用完整记录目标快照，不更改ADR-007或旧dataset build。目标观测只要有一项不合格或多观测上下文无法区分，整个record不准入；规则版本1仅支持以有效、不同的time_on_stream区分多个同目标观测。组成相同或观测ID不同本身不足以判断独立样本。

资格清单按内容哈希标识，冻结前重查全部输入以发现过期清单。快照与资格清单的关联作为只追加JSON放在快照旁qualifications目录，不增加数据库表或迁移要求。关联写入不与快照跨介质原子提交，路径故障可产生已有快照但缺关联的中间状态，修复后幂等重试；当前不支持多用户并发仲裁。

## ADR-012：TheMeCat 补充资料分层归档与实施协调（2026-11-10）

用户请求阅读补充说明和脚本、放置文件并厘清实施方案。两份原件逐字节存入 docs/references/themecat，保留 Downloads 原件；其中嵌入的“给 Codex”指令、模型训练和目录重构建议仅作为资料审查，不自动扩大本次执行范围。

本阶段方案以 TheMeCat v1.0 为唯一外部结构化文献主数据源，同源原始论文/附录用于复核。复用现有模块化单体、SQLite、哈希 raw、staged/curated、审核和快照，不另起 processed/模型库或空合成表。长期合成工艺研发保留；当前数据只支持有证据的组成/工况任务，未报告工艺不补造。

新增 scripts/validate_themecat.py 作为独立标准库审计工具；原始 pandas 脚本仅归档。独立工具保留原始字符串与行号，区分全空/非空、缺失/无效，输出到新目录；默认不套公式，显式启用也只产生假设性诊断，不替代 govern/review/qualify。不新增核心依赖。

官方论文定义解决数据集级 mol% 和质量流量基准，但不自动构成逐行核验。论文规模和文件规模分别保留，原因待查；不强行并成 44 篇。许可元数据按 Zenodo API 留证，区别于论文与原始文献许可。

专项顺序为 B1 语义与治理 v2 → B2 修订重治理 → B3 原文核验 → B4/I1 资格冻结 → I2–I4；见[实施方案](themecat_implementation_plan.md)。这调整 ADR-010 后续切片的真实数据前置顺序，未改变现行数据契约、规则版本和严格快照行为。未来派生列与逐目标冻结需另立版本，不通过删观测或解除 block 绕过当前门禁。

## ADR-013：I4 固定参数论文留出基线（2026-11-10）

I4 采用现有唯一冻结目标 CO₂ 转化率和既定 DOI 论文留出，比较均值 Dummy、Ridge 与 Extra Trees。仅在训练集拟合词表、缺失填补和缩放，以验证 MAE 在三个固定模型中选择；选定后才评价测试集，不在验证集上重新拟合。没有交叉验证或超参数搜索；若以后引入，每折必须从原始受限输入重新拟合词表和预处理，不能直接复用当前最终训练集词表。选择结果及全部基线测试指标保存在同一运行清单中。

建模依赖作为可选 extra，模型序列化文件和锁文件哈希随报告留存。对缺失工艺信息不补造，对来源接受、绝压假设和未知样品关联的限制保留；探索性基线不等于逐条原文核验、样品留出评估或适用域内可用模型。

## ADR-014：I5 只输出有条件的诊断和候选（2026-11-10）

以 I4 冻结的 Extra Trees 模型计算验证集 SHAP 和置换重要性；以训练数据排除同论文的最近邻距离建立启发式域阈值，独立记录未见物种及工况越界。树间分散度及 ±2 标准差覆盖仅作经验诊断，不赋予置信度或覆盖保证；按论文报告覆盖和误差，说明 I4 测试集已被查看。相关或缺失特征的解释不作因果推断。

筛选仅接受操作者提供的候选、共同工况及设备、兼容性、前驱体与成本/风险证据；程序执行明确的组成、物种、工况和启发式距离过滤，不核实证据真实性。合成计划写入候选卡但未进入当前模型。结果限 proposed/caution、默认四槽最多六槽；欠缺输入时停止，不虚构工艺或实验结果。当前未取得真实候选与约束证据，因此未执行真实筛选或批次规划。

## ADR-015：先完善特征工程与预测能力，模型尚未定型（2026-11-10）

用户重申此前共识：先打通并完善上游，从特征工程和预测建模开始，实验属于后期。当前开发重点为总体C及辅助其评价的D；ADR-014的筛选边界继续有效，但已有接口和探索清单不代表当前应推进E/F。不把候选工艺、设备、前驱体或实验准备作为当前特征/预测能力建设的前置条件。

Extra Trees是I4在一次既定论文划分上从Dummy、Ridge和Extra Trees中选出的工作模型，服务于该次运行和I5诊断，并非平台最终算法或参数决策。初版物种mol%与工况特征同样是比较基准，最终特征方案、预测模型及其适用范围仍须通过版本化比较和分组评价确定。

近期路线为特征工程完善 → 模型比较与分组评价 → 绑定特征处理和模型的独立预测入口；甲醇相关目标按真实覆盖逐步扩展。组成相对工况的增益对照是模型评价的一部分，不能取代完整预测管线建设。B3继续暂缓，不补造工艺数据；现有测试集作为已查看的历史参照，模型选择在训练侧按组验证。具体交付与失败行为见[当前进度](progress.md)。本条只记录方向与优先级，不声明已实现新特征、模型或预测接口。
