# Cat_AI 项目：活性相与催化剂物化属性描述符解决思路（v0.3）

> 2026-11-12用户澄清后的修订：本文仍为候选方法池，实际范围见[实施方案v0.4](feature_engineering_plan_v0.1.md)。先S1准备近期所需特征数据、导入/数据库及计算模块，再S2完善模型和训练预测框架，同时交付用户参数入口，最后S3运行验收。R1/R2仅作基础/增强实验预设，不再代表开发先后。近期物化只实现电负性、共价半径和来源角色统计，其余按证据后续引入。

**研究对象**：CO₂ 加氢制甲醇；覆盖 Cu 基、In₂O₃ 基、ZnZrOₓ 基、Pd 基等不同催化剂家族。  
**目的**：建立跨家族统一预测模型 A 的合理材料表示，并为满足覆盖条件的单家族模型 B1（相同通用特征）/B2（家族专属特征）提供可比较的基础。  
**定位**：特征工程设计方案，尚非经验证的最优描述符组合。

## 1. 总体判断

- **研究物化属性作为材料表示的价值**，避免仅依靠催化剂类别标签。近期R1保留物种/含量表示，R2检验少量物化增量，不预先断定物化属性已优于组成基线；是否转向独立物化表示由后续分组验证决定。
- **不能把元素属性等同于活性相属性**。Cu 金属与 In₂O₃ 氧化物存在相态、成键和氧化还原特征差异；需要“元素性质 + 活性相化学组成/名义化学态”，必要时再考虑结构和表面性质。
- **保持组分功能角色**：活性相、载体/关联氧化物、助剂分别描述，再构造它们之间的比例和属性差异；不把整个催化剂的所有元素直接混合求平均作为核心特征。
- **坚持配方设计时可获得**：用于虚拟筛选的主模型，优先采用化学组成即可确定的属性；BET、粒径、氧空位、吸附能等可能依赖制备和工作态的量，进入后续结构增强模型或计算增强模型。
- **属性应由科学假设提出、再由预测验证筛选**：不能把单一 SHAP 高重要性视为已发现的催化机理。

## 2. 物化属性如何选定

先按 CO₂ 加氢制甲醇涉及的物理化学作用提出候选属性，之后依据**可获得性、定义统一性、数据库覆盖、实际预测增益**逐步筛选。

| 物理化学维度 | 候选描述符（非全部近期必做） | 解释与使用限制 |
|---|---|---|
| 电子特征 | Pauling 电负性、第一电离能、价电子构型（如 s/p/d 占据） | 元素属性，主要是材料组成的间接代理；不等于真实表面电荷或 H₂ 活化能垒 |
| 几何/成键 | 共价半径及活性相—助剂/载体的半径差 | 与原子尺度及配位倾向相关；差值不等于真实界面匹配或结构稳定性 |
| 化合物组成 | 金属阳离子组成、名义 O/M 比 | 能区分金属和已知化学计量氧化物；不能用以推定真实氧空位浓度 |
| 化学态 | 可明确确定的名义氧化态 | 属于化学式/价态假设，不代表原位工作态；多价态或不定比情形标注不确定 |
| 氧化还原与热力学（R2之后） | 氧化物形成能/形成自由能等 | 必须规定晶相、参照态、计算/实验来源；不应混用不同基准 |
| 反应相关表面性质（后续） | 氧空位形成能、H₂ 解离能、CO₂/关键中间体吸附能 | 与催化机理更直接，但强烈依赖晶面、缺陷、覆盖度和计算条件，不作为首版通用必填特征 |

**近期R2只实现电负性与共价半径。** 第一电离能、价电子构型（需固定编码）、名义O/M、名义氧化态及形成能属于后续候选池，按来源、覆盖和增益逐项引入，不预设每项都有效。

## 3. 怎样从具体配方生成特征

本节描述后续物化研究的方法。R1/R2只沿用来源角色`compound`/`support`，R2映射为`reported_active`/`reported_support`，不宣称已确定真实活性相；中心元素按显式白名单计数（包括Si等经定义的中心），不以通用语法解析或机械删O替代语义确认。碳酸根中的C不自动加入中心统计，具体定义以实施方案第4节为准。

### 3.1 活性相

1. 保留可追溯的化学身份：例如 `Cu`、`In2O3`、`ZnZrOx`，以及来源描述的主要活性相及其证据状态。
2. 对化学计量明确的相，解析元素计数，计算**活性相中金属元素的原子分数**，据此生成电负性、半径、第一电离能等加权统计量；必要时保留范围、最大值和差异量。
3. 记录名义 O/M、名义化学态等化合物层面信息。金属 Cu 的 O/M 可明确为 0；对不定比 `ZnZrOx`，如果 x 未知，则 O/M **未知**，不能猜测。
4. 活性相的含量与属性分别保留，例如 `active_loading` 和 `active_mean_en`；物性均值并不能替代实际配方比例。

### 3.2 载体和助剂

- 对载体、关联氧化物、助剂按照同一化学式解析能力生成**角色专属**物性：`support_*`、`promoter_*`。
- 保留组分含量及活性相—助剂/载体之间的差异，例如 `delta_en_active_promoter`、`delta_radius_active_promoter`；差异应具备明确的计算方向。
- 多助剂/多载体情形，采用**角色内组成加权统计 + 总含量**，并在需要时记录数量及离散程度；避免无定义的“助剂1/助剂2”顺序影响结果。
- 催化剂家族与活性相角色不能仅凭元素含量机械确定。对于 Pd/In₂O₃、Cu–In 复合材料等，应有分类来源、置信状态及可复核规则；含糊材料允许标记未知/复合，而非强行归类。

### 3.3 特别注意 TheMeCat 的组成基准

现有 TheMeCat 使用的是**材料组分 mol%**，不是元素原子分数，也不能直接当作元素 wt%。必须先根据每个**可解析的组分化学式**把材料组分计数展开，再计算对应范围的元素原子分数。

例如，假设材料组成是 70 mol% `In2O3` 和 30 mol% `ZrO2`，金属阳离子归一化后：

\[
x_{\mathrm{In}}=\frac{0.7\times 2}{0.7\times 2+0.3\times 1}\approx0.824,\quad x_{\mathrm{Zr}}\approx0.176.
\]

这里的 0.824/0.176 是整个示例配方**金属阳离子**比例，不应误作 `In2O3` 相内部的 In 原子分数。若源数据未明确全材料组成基准、相组成不定比或化学式无法解析，应拒绝生成依赖这些假设的特征，并输出可解释的原因。

## 4. 属性数据来源与质量控制

- R2优先采用经核实、固定来源版本的小属性表和显式物种映射，不强制引入`pymatgen`/`matminer`；若后续采用这些库，仍固定版本及属性口径，不直接默认引入Magpie全集。
- 记录每一个物性字段的 **property_id、定义、单位、数据源、版本、计算规则、适用范围、缺失原因**；为属性字典和生成结果保存版本/哈希。
- 统一采用一个约定明确的半径体系（如共价半径）与电负性标度（如 Pauling），不混合来源口径。
- 区分 **真实零值、没有该属性、不适用、未知、化学式解析失败**。不得把未知氧化态、氧化物形成能或氧空位特征填 0 冒充真实物性。
- 特征生成在训练/推理中使用同一计算实现、映射和属性表。R2仍含物种词表，训练未见的正含量物种角色键在独立预测中拒绝；不能仅因元素属性可计算便声称支持其外推。

## 5. 与当前 Cat_AI 代码如何衔接

当前仓库已经有 `src/catalyst_ai/features/design.py` 以及组成/工况特征、论文分组、单目标基线和诊断链路。**采用新增模块 + 版本化切换，不覆盖现有特征定义和历史报告。**

近期模块落点以实施方案第5节为准，S1须先落实导入、存储和计算；S2同步提供可配置训练预测。下列细分模块仅为后续职责拆分候选，不要求全部提前建设：

- `features/chemistry.py`：化学式解析、化合物计量校验、不定比识别。
- `features/properties.py`：元素物性字典与版本化读取。
- `features/roles.py`：活性相、载体及助剂的角色解析、来源状态和歧义审查。
- `features/physchem.py`：按角色计算统计属性、差异量、可用性/缺失原因。
- `configs/feature_sets.yaml`：按版本定义特征，固定物性列表和计算规则；近期F0/F_cond/F_base/F1/F2定义见下表，F3留后续另定。
- 输出独立的特征覆盖报告，包括各家族覆盖、不可解析组分、缺失机制与训练未见元素比例。

**遵守现有科研边界**：训练集拟合词表、填补和缩放，仅发生在训练折；保持快照与分组不可覆盖；不将文献 DOI、产品性能、实验后的表征结果当作可用于未知配方设计的输入；不改变 TheMeCat 原始组成语义。

## 6. 特征集消融与模型评估

| 特征组 | 特征构成 | 验证问题 |
|---|---|---|
| F0 | 原`design-features-v1`及旧缺失处理 | 仅保留历史语义和报告，不直接作为R2增量基座 |
| F_cond | 四项核心工况 | R1材料信息增益对照，不自动作为工作模型 |
| F_base | 四项工况＋完整来源角色/物种材料mol% | R1工作特征集；R2需在同一子集重训作基准 |
| F1 | F_base＋reported_active含量、正含量物种数、电负性/共价半径均值，共4项增量 | 来源active角色统计是否带来增益？ |
| F2 | F1＋reported_support同样4项＋active减support两项属性差，共10项增量 | 增加载体来源角色统计是否有增益？不推断真实协同机理 |
| F3（后续另定） | 有条件的结构/热力学增强候选 | 另定输入可获得阶段、口径与版本，不属于R2 |

后续有可靠家族标签时，可研究“仅家族标签”以及“物性＋类别标签”；R1/R2不以家族名称为输入，也不等待家族分类完成。

- **当前真实进展**：TheMeCat 已冻结593条 CO₂ 转化率记录，已有一次论文分组基线。现阶段首先以 CO₂ 转化率完成特征方法比较；不能将其结果表述为甲醇STY或选择性模型。
- 默认基准固定3折DOI验证，OOF论文等权MAE选模；用户自定义模型/参数单独记录，不自动搜索；R1比较F_cond/F_base，R2在同子集比较F_base/F1/F2。既有已查看test仅作历史参照，validation不重新选模。F0与R1的处理语义不同，不以其历史成绩直接推断物化增益。
- 报告总体及按家族的 MAE/RMSE/R²（家族样本过少或目标无方差时明示不可算），以及已知/未见配方覆盖、解析失败率和模型适用域。
- S2同期检查家族标签和论文覆盖，满足条件时比较`A`（跨家族训练）与`B1`（单家族、相同特征），不足记录跳过原因。`B2`（单家族、专属特征）在专属特征有依据后加入；分别识别数据共享和专属特征的增益，不直接以A对B2推断共享作用。
- SHAP/置换重要性用于发现潜在规律与冗余，不直接证明机理因果；属性是否保留以**分组泛化与可重现性**为准。

## 7. 推荐的实施次序与验收

1. **S1-A需求/导入/数据库：** 区分已有字段、需导入属性和需计算特征；先核实并导入两项属性及物种中心计数白名单，版本化入库，来源/缺失/冲突可追踪。
2. **S1-B计算与特征：** 独立模块生成角色均值/含量/差值，构建F_cond/F_base/F1/F2所需输入及覆盖报告；验证碳酸盐计量、缺失/不支持、同角色换序和同物种合并不变。
3. **S2模型框架＋参数入口：** 完善训练/评价/保存/重载和独立预测，同时提供用户选择受支持特征、模型及合法超参数的配置/Python/CLI入口；同期检查通用/单家族对照资格，满足就比较，不足记录原因。
4. **S3运行与验收：** R1基础、R2增强是同一框架下的实验预设，同子集对照；再运行自定义参数训练和指定模型预测，公开误差和支持率，验证配置追踪和重载一致。

验收关注计算可重复、导入/数据库有据可查、训练预测处理一致、参数入口可用；无增益也可完成工程交付。真实角色判定、更多元素属性、家族专属特征及结构增强仍按覆盖和证据逐项扩展，不以全部候选属性齐全阻塞近期开发。

## 8. 现阶段不做的事

- 不为了跨材料统一而强制所有催化剂共享一个错误的活性位点机制标签。
- 不从材料名称臆造氧空位浓度、吸附能、界面面积或工作态价态。
- 不在没有统一晶相/参照态的情况下混用形成能。
- 不把单次整体随机划分的高 R² 当作新催化剂配方泛化能力。
- 不把当前 CO₂ 转化率基线直接用作甲醇产率优化证据。
