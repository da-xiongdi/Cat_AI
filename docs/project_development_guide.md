# AI辅助CO₂加氢制甲醇催化剂开发平台 — VS Code项目开发指引

> **版本：v0.2｜基线日期：2026-11-09｜状态：开发规划，不代表已实现**  
> **目标读者：** VS Code/Codex及项目开发人员  
> **用途：** 作为项目需求、数据契约、技术架构、阶段任务和验收边界的统一依据。若与后续真实实验数据/项目决策冲突，须记录变更并更新版本。

## 0. 一页摘要：我们到底要实现什么

构建一个**面向多材料体系**的CO₂加氢制甲醇催化剂AI研发软件系统：从文献和自有数据中抽取、核验并管理**催化剂组成、制备条件、表征信息、测试工况与性能指标**；训练具有适用域与不确定性说明的性能预测模型；做可解释分析、约束下虚拟筛选、组成与合成工艺优化；推荐可合成、可测试的候选配方；未来连接最多4–6个并行测试通道，将结果回灌并迭代模型。

**总路线：**

`文献/自有数据 -> 证据化入库与质量治理 -> 分层描述符 -> 性能预测及解释 -> 有约束的优化/虚拟筛选 -> 候选配方与实验批次 -> 实验验证 -> 模型反馈`

**当前优先顺序：先“上游”，后“设备”。** 优先让数据→模型→候选推荐流程能离线运行、复现、审计。第一阶段不开发仪器驱动、实时控制、自动合成，也不以Web界面替代后端研究能力。

### 0.1 必须遵守的设计约束

1. **材料体系开放。** 不把模型或数据表写死为Cu/ZnO/Al₂O₃；Cu基、In₂O₃基、ZnZrOx及其他体系都应能录入。模型可按体系进行专用建模，但平台的核心数据结构必须通用。
2. **合成参数是正式输入。** 组成、制备工艺、工况都要进入“可设计/可预测”的特征空间；表征数据是另一类“制备后才可获得”的特征，不能在推荐尚未合成的配方时错误使用。
3. **工况差异不能任意换算为统一性能。** 保留原始测试工况；默认作为模型输入/分层条件，只有定义一致、物理依据充分时才进行派生与换算。
4. **可追溯且可复现。** 每条训练记录追溯到原始文献DOI/页码/图表/测试条件或内部实验编号；每次模型/筛选都关联数据版本、代码版本、配置、随机种子和输出物。
5. **预测必须说明适用域与不确定性。** 跨材料体系和小样本外推不得作为“已验证性能”宣传。模型评估与科研验证不能混淆。
6. **实验资源有上限。** 每批最多4–6个催化剂，默认按4个槽位配置；推荐时兼顾性能、信息增益、候选多样性、可制备性和对照/重复样。
7. **证据状态严格区分。** “规划内容”“已实现功能”“已验证成果”三类不可混写；没有新增证据，保持未知/待验证，不生成虚假的实验配方或性能结果。

## 2. 科研问题与评价目标

### 2.1 三个核心科研问题

- **Q1 数据：** 不同文献的制备路线、结构、测试条件和指标如何融合？怎样保留可比性和证据质量？
- **Q2 模型：** 能否在数据稀疏、跨材料体系的情况下，学习“**元素组成 + 合成工艺 + 反应工况 → 性能**”的关系，并检验其泛化能力？
- **Q3 设计：** 怎样推荐**可制备且值得实验**的材料/工艺组合，而不只是挑选训练集中已经出现的高分记录？

### 2.2 评价指标（允许部分缺失，不强行补全）

优先支持：CO₂转化率、甲醇选择性（需明确碳基等定义）、甲醇收率、甲醇时空产率STY；扩展支持稳定性/失活速率、重复性、可合成性、材料/工艺成本。第一轮训练目标由**真实可用且口径一致的数据覆盖情况**决定，不能预先声称某项指标可有效预测。

**两种推荐模式必须区分：**

- **催化剂设计模式：** 改变组成、合成路径及工艺参数；反应测试条件固定在指定窗口或作为条件约束。
- **反应工况优化模式：** 固定给定催化剂的组成/制备信息，只改变温度、压力、空速、配比等反应参数。

禁止在同一张“最优配方”表里混合不同测试工况的性能预测，却不向用户说明差异。

## 3. 数据库方案：实体关系及字段

### 3.1 数据源

1. **文献数据：** 期刊论文、附录/补充信息、经许可的公开结构化催化剂数据集。可调研 `TheMeCat` 等候选来源，但**接入前必须核实来源、许可、字段、覆盖范围、重复项与可比性**，不得默认可直接使用或保证质量。
2. **自有实验数据：** 未来导入催化剂设计/批次记录、合成工艺、表征及测试原始表格；独立标记访问权限、保密等级、版本。
3. **知识/规则：** 来自文献或专家的制备约束、原理假设和经验规则；**将观测事实、经验判断和待验证机理假设分开存储**。

### 3.2 最小实体模型（不要把所有信息塞进“一个催化剂一行”）

| 实体 | 粒度 | 重要字段 / 关联 |
|---|---|---|
| `source_document` | 一篇文献/一个内部资料 | `source_id`, DOI/标题/年份/授权与权限、文件指纹、来源类型 |
| `extraction_record` | 一次抽取/人工复核 | `source_id`, 页/表/图/补充文件、原文片段定位、提取方法/版本、复核人、状态 |
| `catalyst_recipe` | 一个名义催化剂配方 | `recipe_id`, 材料体系标签、元素/化合物及摩尔或质量配比、载体、助剂、组成基准 |
| `synthesis_run` | 配方的一次真实制备 | `synthesis_id`, `recipe_id`, 合成路线、前驱体、pH、老化、干燥、焙烧、活化/还原、各步骤条件、批次 |
| `characterization` | 一次样品表征 | `synthesis_id`, 技术、物相、BET、分散度、粒径/缺陷等、测量单位与条件 |
| `test_run` | 一次性能测试实验 | `test_id`, `synthesis_id`, 反应器类型、T/P/GHSV、进料组成、质量/稀释条件、稳定化时间、运行时长 |
| `performance_observation` | 一个测试时间点或指标 | `test_id`, metric、数值、原始单位、归一单位、时间/误差、计算定义、碳平衡 |
| `knowledge_rule` | 一条假设/经验/约束 | 规则内容、适用材料体系、依据来源、证据等级、可证伪性 |
| `dataset_snapshot` | 一个不可变的训练数据版本 | 查询/筛选条件、样本ID列表/哈希、清洗版本、目标变量口径、划分策略 |
| `model_run` | 一次训练 | 快照ID、模型类型、配置、随机种子、评价、解释报告、文件路径/哈希 |
| `screening_run` / `candidate` | 一次筛选及其中一候选 | 搜索空间、约束、目标、模型ID、预测、不确定度、可合成性、排序理由 |
| `experiment_batch` / `feedback` | 一批实验及反馈 | 候选ID、实际制备条件、测试数据、对照样、结果核验、模型回灌关联 |

说明：**同一催化剂配方可能有多个合成批次；同一批次可能有多个温度/压力/空速下的测试点；一篇文献可能含多个配方和测试条件。** 以此避免把不同实验错当作独立材料，或出现一对多关联丢失。

### 3.3 v0.2字段字典：五大维度

| 维度 | 核心字段（示意） | 规范要点 |
|---|---|---|
| 组成与结构 | 元素及配比、计量基准、载体、助剂、物相、BET、粒径、分散度、表面缺陷 | 元素组成同时保留原始 wt%/mol% 与转换依据；无关材料体系的专用字段应允许不适用 |
| 合成方式 | 制备路线、前驱体、添加顺序、沉淀pH、老化/干燥/焙烧/还原的温度/时间/气氛、升温速率 | 保存步骤序列；“未报告”“不适用”“明确为0”不可混淆；处理变量范围及依赖约束 |
| 测试工况 | 反应温度、压力、GHSV及体积基准、H₂/CO₂/CO/惰性气组成、催化剂装填量、测试时间、反应器 | 压力注明绝压/表压；空速注明标准状态和体积基准；进料组分应做守恒/闭合检查 |
| 催化性能 | 转化率、甲醇选择性、收率、STY、稳定性、误差/重复次数、碳平衡 | 记录选择性碳基、STY质量/体积基准及单位；不同口径不可混为一类目标 |
| 专家知识 | 催化机理假说、元素/工艺可行域、禁用组合、成本、安全、合成经验、证据等级 | 规则需附来源和适用条件，不得把专家意见直接标为实验观测 |

与现有本地工作台36字段兼容时，建立 `legacy_field_map.yaml` 做字段映射；**不要用原有HTML内的浏览器本地存储作为科学数据的唯一数据库**。

### 3.4 每个数值必须保留的通用元数据

`raw_value`, `raw_unit`, `normalized_value`, `normalized_unit`, `definition`, `source_locator`, `extraction_status`, `quality_flags`, `uncertainty`, `provenance`。

推荐强制ID：`source_id`, `recipe_id`, `synthesis_id`, `test_id`, `observation_id`；不要仅靠“论文标题+材料名称”去重。

### 3.5 数据质量与可比性规则

- 单位规范：T 可统一为 °C/K 之一供计算，但原值不删；P 统一为 bar(abs) 之前必须知道压强类型；GHSV在基准不明时仅保留原值并标记风险。
- CO₂转化率、选择性均保留定义；仅当转化率与选择性具有相同计量基准、进出口定义和适用条件时，才允许计算甲醇收率 `Y(%) = X_CO2(%) × S_MeOH(%) / 100`。若存在CO参与或定义差异，先确认碳归属，不能套用。
- STY换算仅在流量、装填质量/体积和单位基准齐全且口径一致时进行；不能凭转化率、选择性就无条件推定STY。
- 不同文献的T/P/GHSV/进料比不能简单换算到一个“标准测试工况”后宣称严格可比；默认保留为特征，适当做工况分层/匹配。跨工况外推须标注风险。
- 缺失分类：`not_reported`（未报告）、`not_applicable`（不适用）、`invalid`（无效）、`not_measured`（未测）、`zero`（真正为零）。
- 检查：单位是否合法、配比是否闭合、进料是否闭合、性能指标是否在合法区间、重复/冲突、同源复制、极端值、来源/页码缺失、字段质量分级。
- 数据抽取：PDF/表格/OCR/LLM仅产生**待复核草稿**；每条进入“已核验训练集”的关键数据必须有可回溯定位和按策略执行的人工复核。禁止虚构未报告的制备条件。
- 数据集快照只引用核验后的记录，永远不覆写原始数据和来源标识。

## 4. 特征工程：为“能预测”和“能推荐”分别设计

### 4.1 三层输入与两条模型轨道

| 特征层 | 内容 | 何时可用 |
|---|---|---|
| **A 设计前可知** | 元素、比例、元素属性聚合描述符、载体/助剂、合成路线与计划工艺参数 | **新配方尚未合成时即可用于推荐** |
| **B 测试工况** | T、P、GHSV、进料气组成、时长/条件 | 决定目标条件下预测，需要固定/受约束 |
| **C 制备后表征** | BET、物相、晶粒尺寸、分散度、氧空位等 | **只有实验表征后**才可用于诊断/改进模型 |

- `DesignModel`：A+B→性能。**配方推荐的主模型**。
- `DiagnosticModel`：A+B+C→性能。用于研究结构性能关联、已合成样品诊断及机制辅助解释，不能在新配方尚未测得C时暗中依赖C。

### 4.2 描述符优先级

1. **基本：** 配比归一化、元素/化合物存在性、组成比例、载体/制备方法类别、连续制备条件和测试条件。
2. **通用元素属性：** 加权原子序数、原子半径、电负性、氧化态等统计量；注明来源/算法、缺失处理与适用性，不依赖某个特定体系。
3. **可选扩展：** 结构表征、文献知识标签、材料体系嵌入、物理/化学先验；均应可关闭并比较增益。

严禁使用测试结果、测试后表征、同一实验的下游派生目标等泄漏信息作为设计阶段输入。对于原文缺少关键合成参数的记录，可保留为训练低质量子集或仅用于描述统计，是否准入由可追溯规则决定。

## 5. 模型训练与验证方案

### 5.1 基线先行，不急于复杂算法

- **基线0：** 简单均值/分层均值、Ridge/ElasticNet等，检验数据和任务是否具备预测意义。
- **基线1：** Random Forest、HistGradientBoosting等树模型；可选择性尝试CatBoost/XGBoost，但非首阶段硬依赖。
- **路线比较：** `全体系通用模型` 与 `材料家族专用模型` 同时评估。专用模型可能有效，但当样本不足时必须保留“不足以训练”的结论。
- **单目标先跑通：** 用一项字段充足的真实性能指标建立可复现训练流程，再扩展多目标、稳定性。

### 5.2 分组切分（核心验收要求）

至少同时报告：

- **Group by source/paper：** 同一文献的系列样本不能同时混入训练集和测试集，以检验文献迁移表现。
- **Group by recipe/synthesis：** 相同配方/制备批次的不同工况测试点按组分开，避免“同一催化剂记忆”导致指标虚高。
- **Material family holdout（条件允许时）：** 留出某一材料家族，检验跨体系迁移；若训练覆盖不足，明确标示无法可靠评价。

指标按目标特性选择MAE、RMSE、R²，并给出测试集样本量、材料家族覆盖、工况覆盖及基线对照。模型训练时必须持久化随机种子、分组标识和划分结果。

### 5.3 不确定性、适用域与解释

- 先支持集成模型预测分散度/自助采样等**经验性不确定度**，再视校准样本量试行分组保序的区间校准；**不保证未经验证的区间具有真实覆盖率**。
- 针对成分与工况建立距离/邻域/分布外（OOD）判定，候选展示 `in_domain / caution / out_of_domain`。
- 用Permutation Importance和SHAP分析变量贡献，记录相关特征的解释不稳定性；**SHAP不等于物理因果或机理证明**。
- 若数据不足以验证，输出“证据不足/模型不可用”，不输出看似精确的“最优性能”。

## 6. 虚拟筛选、优化及主动学习

### 6.1 候选设计空间

候选对象需完整记录：`元素种类 + 比例 + 载体/助剂 + 合成路线 + 合成参数 + 目标测试工况`。生成过程必须验证组成闭合、材料/工艺兼容、设备能力、温压安全边界、可获得前驱体、项目设定的成本/风险阈值。

初期通过**人工配置有边界的搜索空间** + 规则筛选 + 批量模型预测运行；不要要求模型完全“从无到有发明合成路线”。允许选择“已知材料体系邻域探索”和“跨材料体系探索”两种模式，后者增强风险提示。

### 6.2 优化次序

1. **可运行MVP：** 随机/网格候选生成 → 合法性过滤 → 性能及不确定性预测 → Pareto/加权排序 → 输出候选卡。
2. **条件成熟后：** 贝叶斯优化（如TPE/GP等与变量类型匹配的方法）、多目标优化、基于预测分散度的主动学习。
3. **方法储备接口：** 可接分步粒子群PSO、SHAP指导的变量缩减，但需与简单基线对比；优化算法不得绕过工艺约束。

### 6.3 推荐不仅看“预测最高值”

每个候选至少包含：

- 候选配方/组成基准/制备工艺明细；目标工况；
- 预测指标与不确定性、适用域标签、使用的模型/数据版本；
- 排序依据与约束检查结果；最近的已知参考材料/证据定位；
- 合成和测量的未知事项清单；`proposed`状态（**不是已验证**）。

**实验批次规划：** 默认4槽、最多6槽。候选组应兼顾“当前高分利用”“高信息量探索”“可重复/对照”，具体比例可配置，不能把4–6都用于同一种高分邻近配方。

## 7. 实验反馈接口（第一阶段先做到能导入）

流程：`candidate -> experiment_batch -> actual_synthesis -> test_run -> observation -> review -> dataset_snapshot(new) -> model_run(new)`。

- 候选计划值与实际制备/测试值必须分表记录，不覆盖原计划。
- 批次状态：`proposed -> approved -> in_progress -> tested -> reviewed -> ingested`（失败/取消另记），每一步留操作者/时间/证据。
- 失败合成、低活性和未成功测试同样保留，以支持后续可合成性/边界学习；不把缺失性能标签当作零。
- 模型反馈必须生成**新数据版本与新模型版本**，比较固定测试集或外部集的变化，不能仅凭数据入库称“AI性能提升”。
- 仪器/文件接口独立于研究核心。设备实际并行能力、通道差异、真实自动化控制待后续核实。

## 8. 软件架构与技术选型（建议实现，不是已经部署）

### 8.1 架构原则

使用**Python模块化单体 + 命令行/脚本优先 + 分层文件存储**；先保证数据和算法能独立复现，再添加UI/API。避免第一阶段引入过多微服务、消息队列或复杂部署。建议 Python 3.11+（具体版本按开发环境锁定）。

- **元数据与实体关系：** SQLite + SQLAlchemy（后续可迁移PostgreSQL）。
- **训练表与快照：** Parquet（pandas/pyarrow），附schema与哈希；原始数据只读留存。
- **字段与入库校验：** Pydantic、显式Python校验规则；可选Pandera。
- **机器学习：** scikit-learn起步，SHAP/Optuna等作为按需引入的插件依赖。
- **可视化：** 第一阶段生成本地Markdown/CSV/HTML图表报告即可；后续可用Streamlit构建管理页，必要时再接FastAPI。
- **配置：** YAML；**追踪：** JSON日志 + 固定目录结构和哈希清单；后续如有需要再引入MLflow。
- **自动化测试：** pytest；静态检查ruff；类型检查按需。

## 9. 开发任务分解（严格顺序）

| 优先级/任务 | 需实现功能 | 阶段验收 |
|---|---|---|
| **A — P0 项目骨架与数据契约** | 建目录、打包环境、领域实体、字段字典、schema校验、统一CLI、pytest与示例数据标识 | 新环境可安装运行；数据实体关系及关键约束自动测试通过；没有虚假业务初始数据 |
| **B — P0 数据接入与治理** | CSV/JSON文献适配器、来源溯源、原值/标准值、质量规则、复核状态、快照；公开数据源接入审计 | 示例导入能被追踪到来源行；有违规工况/缺失/重复报告；未经审核不能进入已核验训练快照 |
| **C — P0 特征与基线模型** | A/B/C描述符、训练数据构建、分组切分、Dummy/Ridge/树模型、评价、模型与配置持久化 | 使用被核验的数据运行并有可复现报告；可检测同源泄漏；数据不足时如实失败/跳过 |
| **D — P1 解释及适用域** | 特征重要性、SHAP可选、子组评估、不确定度与OOD检查、模型卡 | 输出解释与局限；出域候选显示警示；无可用验证时不声称可信 |
| **E — P1 虚拟筛选与推荐** | 有界候选空间、工艺约束、条件化预测、Pareto排序、候选卡/CSV、实验批次计划 | 配方和合成条件可追溯；无效配方被过滤；超4–6槽被拒绝；没有虚构实验结果 |
| **F — P2 实验反馈及版本迭代** | 导入实验结果、核验、批次状态、失败案例、快照更新、模型重训比较、UI/API可选 | 原计划不被实测值覆盖；前后模型/数据可追踪；真实实验闭环在有证据后才标已验证 |

**本轮启动只做 A + B 的最小纵向切片**（项目骨架、一个示例文献CSV及来源定位、治理报告、快照入口）；不得一开始同时铺开重型前端、模型、优化和自动化设备。

## 10. 逐步验收、质量门禁与演示规则

1. 代码可安装、CLI可调用，`pytest`至少覆盖核心数据契约、单位规则、来源追踪、未知值处理、禁止超容量。
2. 演示数据必须在文件头、metadata及报告中明确标记 `synthetic_demo` 或 `verified_source`；**模拟数据不得加入正式研究训练结果**。
3. 任何单位归一化失败、来源缺失、关键性能定义不清晰均须触发 `warning/block` 等质量标志，不允许静默推测。
4. 支持多配方/多批次/多工况一对多测试记录；测试集切分须防止同论文、同配方信息泄漏。
5. 所有产物带时间、数据/配置/代码版本和模型ID；可以重复运行得出一致结果（随机算法在固定种子/环境下）。
6. 没有足够的核验训练样本时，提供流程空跑/结构测试，不输出“发现高性能催化剂”之类结论。
7. 每个任务完成后更新 `docs/progress.md` 的 **规划内容 / 已实现功能 / 已验证成果**，并写证据文件/测试命令；状态不是凭口头宣告变更。

## 11. 本项目明确暂不做的事

- 第一轮不做自动控制设备、直接驱动实验装置、在线闭环优化或自主无人实验室。
- 不预设单一材料体系或仅对CZA有效的固定特征集。
- 不把文献中的异质测试结果无条件转换成同温同压的“可比真实性能”。
- 不把LLM生成文本等同于真实数据，不自动补齐未报告的催化剂配方和合成条件。
- 不把优化器给出的高分预测当作实测成功，或把已有方法储备当作本项目科研成果。
- 不追求“一步到位的完整网页平台”，优先保证数据与模型研究核心独立工作。
