# D 阶段实施分解：模型解释、适用域与独立验证

截至 2026-11-18，D 阶段已有总体要求和历史 I5 诊断，正式管理库尚无 D 阶段任务。本文把 S3 验收后的工作拆成 D-01～D-07。这些编号用于本实施计划，正式任务及验收随实际执行登记。依据见 [开发指引 §5.3](project_development_guide.md#53-不确定性适用域与解释)、[当前进度](progress.md)、[S3-01 验收](s3_01_acceptance.md)和 [S3-02 验收登记](../artifacts/reports/s3-02-20261118-02d/registration.json)。

本轮目标是确定当前 CO₂ 转化率模型在什么输入条件下可用、常在哪些条件下失效，以及哪些结论已获得独立证据。评价对象固定为 S3 R2 的 **F_base/ExtraTrees**。历史 `dataset diagnose` 绑定 I4 的报告、特征和模型格式，可复用诊断思路，当前模型的结果由新一轮诊断产生。见 [S3 模型清单](../artifacts/models/s3-20261118-01/r2/manifest.json)和 [I5 接口契约](api_contracts.md#i5解释经验适用域与显式候选筛选)。

## 1. 执行顺序与交付物

## 2. D-01：第一批实施步骤

1. **固定证据。** 记录模型 `model_id`、包与清单哈希、预测目标和单位、特征及 DOI 分区身份。核对模型包、运行报告、逐条预测表及 S3-02 的实际入口重放记录，记录本次诊断代码和环境。见 [R2 运行报告](../artifacts/runs/s3-20261118-01/r2/report.json)、[逐条预测](../artifacts/reports/s3-01-20261118-01/r2-predictions.csv)和 [入口复核](../artifacts/reports/s3-02-20261118-02a/formal-r2-checks.json)。
2. **逐条核对开发验证集。** 按 `record_id` 在同一候选和分区内对齐 47 条记录及入口重放状态，检查重复、缺行和不一致。已核对的起始计数为 26 条 `ok`、2 条 `caution`、19 条 `unsupported_species_role`。从逐条字段展开 19 条的未见正含量物种／角色键，以及 2 条警示的超范围维度。单条有多个原因时同时保留逐条计数与原因出现次数。
3. **形成分层诊断。** 逐条表保留 DOI、组成签名、入口状态、原因、已知工况、实测值、原始诊断预测、入口可用预测及有限绝对误差。按 DOI、常见物种／角色键、组成见过与否和工况范围汇总记录／论文数、可用率及误差。缺少可信家族标签时仅使用已核实字段分层；样本或 DOI 数较少的组列出实际分母。
4. **核对折外支持。** 对 454 条 OOF 使用 S3 已保存的折内词表状态及预测，核对 102 条 `ok`、172 条 `caution` 和 180 条 `unsupported_species_role`。分开报告全体诊断误差、可用预测误差和入口可用率，标明分母及 DOI 数。历史 test 仅作参照。若新增指标依赖折内编码或距离，按固定折重新构建对应训练侧统计；开发验证使用最终包的原 train 统计。
5. **交付并复核。** 保留逐条 CSV、分层指标、诊断摘要、执行入口和可校验的输入清单。在新目录保存输出，使复跑可对齐同一记录、状态和原因。以输出一致及失败归因可追溯为通过条件，性能高低作为诊断结论。见 [S3 分母与状态](s3_01_comparison.md)。

D-01 的首个可验收结果是 **47 条验证记录复核表**，其中能定位每条拒绝或警示对应的输入证据。拒绝记录的原始诊断预测仅用于分析模型行为，入口预测值按实际状态保留。

## 3. D-02～D-07：实施检查点

### D-02 当前模型解释

1. 用固定特征变换复现当前包的开发验证预测，在输入可用的子集上检查四项工况、组成特征块及必要的角色特征块。记录分组置换方式、重复次数、随机种子和样本分母。若在编码空间置换，说明其诊断含义和组成闭合、特征共线带来的限制。
2. 报告各块贡献、重复间离散和分组稳定性。可选计算 Tree SHAP，核对特征名、加和与包预测，对应同一评价子集并披露解释局限。样本不足时按实际可解释范围交付。

### D-03 适用域候选规则

1. 以 S3 的输入完整性、未见正含量物种／角色、工况范围及输出状态为基线。对可编码输入，用训练数据建立版本化的组成邻域距离、工况偏离或局部支持量，明确坐标、尺度与阈值形成方式。
2. 用 OOF 与开发验证比较现有提示及候选规则。按域内、警示、域外列出论文等权 MAE、样本及 DOI 数、覆盖率、拒绝原因。训练或选择规则只用开发数据，阈值、代码与版本在独立评价前固定。域标签先作为独立诊断结果，预测入口的行为变更需另做契约和回归验收。

### D-04 独立数据资格与协议

1. 按 DOI 或可追溯的实验来源登记候选数据，核对样品及重复记录与 TheMeCat 已使用数据的潜在重叠，记录来源可追溯性、样品关联及无法确认项。核对目标定义、完整组成、四项工况及单位与参考基准。现有 validation 和已查看的历史 test 继续用于既定用途。
2. 先确定评价所需的独立组数、覆盖范围、重叠处理、纳排原因、指标和样本不足时的报告方式，再冻结数据与规则。如需校准区间，校准组与最终评价组按 DOI 或可追溯实验来源隔离；留存分组证据和标签访问约定。以合格数据和完整协议为独立评价的启动条件。

### D-05 不确定性开发与校准

1. 用当前 ExtraTrees 的树间分散度检查它与实际误差的关系，分开给出样本量、误差与分散度分层。将分散度报告为经验指标。
2. 校准组充足时，按 D-04 固定的组别和名义覆盖率校准并冻结区间算法。D-06 报告实际覆盖率和区间宽度，列出适用分母与计算限制。校准组不足时交付经验诊断，记录区间未校准。

### D-06 独立评价

本轮验收范围为点预测评价流程建设，已交付就绪检查、执行入口和逐条及分层报告。正式独立评价待合格数据，尚无独立性能结论。详见 [D-06 执行流程](d06_evaluation_workflow.md)。

1. 用冻结的模型包、规则和候选数据执行预测，逐条保存来源、状态、原因及输出。按 D-04 协议报告输入资格覆盖、入口可用率及可用子集误差，分别列记录数与独立组数。已实现区间校准时同时报告独立覆盖及宽度。
2. 报告与分母相称的结论。若结果要求重训、改阈值或扩大适用范围，记录为后续版本任务，保留此次评价和协议。

### D-07 模型卡与阶段收口

1. 汇总模型身份、输入要求、入口拒绝、开发与独立评价分母、适用性、解释、不确定性及已知数据限制。模型卡中的状态和数字可回链到固定证据。
2. 按 D-01～07 逐项登记实际交付。证据不足时登记缺项、可使用范围及待补条件，分别记录开发诊断交付和独立验证状态。交接后如需进入 E 阶段，另按候选及工艺约束验收。

## 4. 产物约定

每项使用新运行目录，保留 S3 证据和模型包。D-01 建议目录为 `artifacts/reports/d-01-<tag>/`，输出 `inputs.json`、`row-review.csv`、`group-metrics.csv`、`summary.md` 和执行与校验记录。后续诊断、外部协议、独立结果和模型卡按各自任务版本留存，最终由 D-07 的证据索引串联。
