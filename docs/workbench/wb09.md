交付日期为 2026-11-16，时区为 Asia/Shanghai。

## 入口与交付范围

运行 `uv run catalyst-ai workbench serve --config configs/workbench.yaml`，进入 `/foundation`。

- 来源、字段、治理工作包支持 JSON 对象登记、预览和修订。来源 reviews 保存 scope、actor、conclusion、evidence_version。治理工作包登记要求 name、inputs、rule_version、owner，可补充 reports、reviews、snapshot 及限制。
- `/foundation/samples` 按测试记录分页，只读展示观测、制备与材料关系。原始 Measurement 结构保留原值、单位、ValueState 和溯源信息。
- 字段页展示原型 36 项、五类字典和领域模型映射。自定义字段包含机器键、类型、版本、单位和规则。训练支持范围需要按实际特征构建版本核对，页面显示待核对状态。
- JSON 迁移接受 v1.0/v1.1 的 `version=1` 完整结构和数字或字符串的 4/5/6 容量，保存原始备份字节。旧版自定义字段按已保存值推导类型，缺少观测值时使用 string，并在报告中要求复核。新增字段要求填写类型与版本。
- CSV 使用原型模板，保留中文、多行引号、原始字符串、批次和行号，提供数值错误、重复提示、单位治理提示及领域字段映射。甲醇指标允许留空，CO₂ 转化率可独立保存。发布进入待治理区。
- 预览页可下载批次报告。`/foundation/export` 导出当前台账，完整历史及原始上传文件随管理库 ZIP 备份保存。

## 卡点处理

此前实现已有暂存表与上传表单，缺少字典映射、跨对象关联完整校验及恢复入口。本次补齐模型、筛选、候选、实验和批次引用校验、JSON 数值检查及自定义字段类型检查。同 ID 内容变化提供保留或建立修订，发布事务内再次核对预览时的修订号。过期预览返回冲突，重新上传后可继续。

重复文件沿用批次身份，重复发布沿用记录修订。发布中断时数据库事务回滚，批次维持 staged，可重试。原型来源核验声明和科研状态保留在原始记录中，新的核验范围与固定证据版本另存于 reviews。

## 备份与恢复

页面下载 ZIP，包含 SQLite 一致性快照、全部导入原件/报告/修订、已登记成果文件和 SHA-256 清单。缺失或超出工作区的成果写入 manifest 的 missing 列表。

恢复先验证清单、逐文件哈希、路径、SQLite 完整性、外键和 schema，再校验预览哈希。采用新目录恢复方式，目录为工作区 `backups/restored-<ID>`，其中 `workbench.sqlite` 保存管理库，`workspace` 保存成果文件。恢复事务先在临时目录完成文件写入和工作区路径重绑定，成功后发布目录。

使用恢复副本时，将配置的 workspace 指向恢复目录内的 workspace，将 database 指向同目录的 workbench.sqlite。当前活动项目继续由原配置定位。
