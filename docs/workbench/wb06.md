# WB-06 批量预测执行

2026-11-17 交付。页面入口 `/predictions`，也可从“训练与可解释分析”页面进入。当前执行类型为已登记、已索引且哈希可用的 R1 F_base 模型包；复用原 `load_package`、`predict_one`，不进行训练。

## 启动与操作

安装 `uv sync --extra web --extra modeling`。分别在两个终端启动：

```powershell
uv run catalyst-ai workbench serve --config configs/workbench.yaml
uv run catalyst-ai workbench worker --config configs/workbench.yaml
```

worker 持续领取队列；加 `--once` 处理一个任务后退出，无任务时直接退出。网页不执行预测或加载 pickle。仅选择本地可信、已登记的模型包进行执行；加载时沿用包的模型哈希、依赖版本和特征实现校验。

页面选择固定模型版本，填写 JSON 数组、操作人及可选任务编号。单批 1–1000 行、输入最多 2 MiB。每行格式沿用 `scripts/predict_r1.py` 的 components、temperature_k、pressure_bar_abs、h2_co2_ratio、reactants_flow_nl_g_h。无效行、不支持的物种角色、外推提示和超范围预测沿用原预测入口行为；执行完成不等于所有行都得到有效预测，也不表示科研验证通过。

## 固定输入、状态与恢复

提交在独立目录 `artifacts/workbench-predictions/<job-id>` 保存模型清单、model.pkl、规范输入及执行日志。管理库保存输入哈希、固定模型版本、实现哈希、环境、操作人、任务关联和重试来源；输出目录由服务生成。原模型移动或变化后，重试可使用父任务的固定模型副本，仍需通过校验。

队列状态为 queued、running、succeeded、failed、interrupted、cancelled。独立 worker 在事务中领取工作，每 5 秒更新心跳。超过 60 秒没有心跳的执行在 worker 下一次轮询时标记中断；queued 任务保留。中断、失败、取消后可创建新 ID 的关联重试。取消携带预期修订号，保留原输入、日志和已有文件，不覆盖原执行。结果与模型运行登记在同一事务中完成，并校验 worker 租约；失去租约或被取消的执行不能提交成功。

成功输出逐行 result.json、execution.log，自动登记模型副本、输入、结果和日志的固定成果版本。模型运行台账显示执行成功、研究未审查，保留模型目标、单位、特征、数据、实现/环境及限制。关联管理任务不会自动通过任务验收。加载或执行失败保留错误与日志；页面刷新查看最新状态和日志。

管理库升级至 schema 7 前自动备份。完整备份包含 queued/failed 等任务的固定输入、模型和日志，也保留成功结果、事件及运行台账。恢复运行中的库后，由 worker 按心跳规则核对中断，人工重试创建新运行。

## 接口与验证

GET `/api/workbench/v1/prediction-jobs`、GET `/api/workbench/v1/prediction-jobs/{id}` 查询任务、日志和逐行结果。POST 同名集合接口提交 model_id、version、items、task_id、request_id、actor。POST `/{id}/cancel` 接收 expected_revision、request_id、actor；POST `/{id}/retry` 接收 request_id、actor。沿用本机访问、来源、CSRF、幂等和项目归属校验。

专项回归覆盖独立 CLI worker 与原 Python 数值一致、有效/无效混合批次、固定输入篡改、单次领取、取消阻止成功登记、中断和关联重试，以及备份恢复。全量 pytest 192 项通过，源码检查和格式检查通过。

`scripts/verify_wb06.py` 使用真实 R1 模型执行，运行 Edge 桌面/窄屏提交、独立 worker、逐行结果展示，实际终止独立 worker 后验证中断和关联重试，并核对领域库、原快照及模型哈希不变。只有验证脚本需要额外安装 Playwright 和本机 Edge；生产 worker 不依赖浏览器。验证产物在 `artifacts/reports/wb06-*/verification.json`，包含备份哈希、任务身份和保护文件哈希。
