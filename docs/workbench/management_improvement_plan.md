本计划依据[工作台建设方案 v0.3](../architecture/project_workbench_plan.md)，只安排工作台开发。具体科研任务的目标、方法、排期和验收继续由原任务及专项计划维护。2026-11-18 核查工作区文档和管理库后，将原 WP1–WP5 统一映射为 WB-13–WB-17；WP 仅为旧工作包别名，不单独登记、排期或统计。

## 0. 统一执行顺序与当前下一步

工作台只有一套 WB 任务队列，编号表示身份，执行顺序依据依赖与本次优先级安排。保留 WB-01–WB-12 的原身份和历史进度，不要求按编号把旧待办全部做完后才能启动新增管理能力。

| 执行次序 | 统一任务编号 | 原别名 | 目标与完成条件 |
|---|---|---|---|
| 1：已验收 | [WB-13 管理分类与关联基础](wb13.md) | WP1 | 保留原任务与验收，完成分类、历史交付映射、路线与计划关联的验证，以及正式部署和父任务验收 |
| 2：已验收 | [WB-14 科研路线图](wb14_06_acceptance.md) | WP2 | 路线层级、交互、状态摘要及任务互定位可用 |
| 3：已验收 | [WB-15 下一步工作与计划交接](wb15_05_acceptance.md) | WP3 | 从科研或工作台建设的近期任务节点打开关联的项目计划章节，并查看依赖和计划核对状态 |
| 4：准备开工 | [WB-16 页面整合与维护入口](wb16_implementation_plan.md) | WP4 | 导航、总览、文档及成果分类一致，历史交付与剩余工作可查看 |
| 5 | WB-17 本轮整体验收与部署说明 | WP5 | 新增能力、原功能回归、迁移恢复、浏览器及科研数据隔离验证通过 |
| 本轮之后的优先候选 | WB-07 扩展计算与训练接入 | 无 | 对应科研接口及模型包契约完成交付，具备复用和一致性验证条件后安排 |
| 后续 E 阶段 | WB-11 筛选与候选管理 | 无 | 模型台账及筛选领域契约具备条件，按 E 阶段计划安排 |

本轮默认按 WB-13 → WB-14 → WB-15 → WB-16 → WB-17 逐项交付。WB-14 和 WB-15 的基础开发都依赖 WB-13，技术上可以分别开展，但默认交付顺序保持不变；专项测试随各任务进行，不等 WB-17 才开始验证。P0/P1 标识影响范围取舍，不替代此处排期。

WB-07/11/12 的后续位置是排期安排，不新增它们对 WB-17 的技术依赖，也不承诺前一项完成即自动具备领域条件。条件未满足时保留原待办并显示原因，不为清空 WB 队列实施科研任务。科研任务继续按自身计划推进，不以本轮五项工作台建设完成为前置条件。

**当前下一步是 WB-16-01 开工基线与分类契约。** WB-13 至 WB-15 的子任务和父任务均已通过正式验收。[WB-16 实施顺序和验收条件](wb16_implementation_plan.md#3-子任务与实施顺序) · [WB-15 验收与可复用入口](wb15_05_acceptance.md) · [WB-14 验收](wb14_06_acceptance.md) · [WB-13 验收](wb13.md)

正式库已有 12 条历史 WB 引用，以及 WB-13 的九条、WB-14 的七条、WB-15 的六条正式任务。WB-16 和 WB-17 登记前核对编号占用，通过现有服务建立正式任务，按实际发生时间保存状态与验收。

## 3. 数据迁移与历史整理步骤

1. 只读盘点实际表、schema 版本、任务 ID、历史 WB 记录、文档及现有固定验收引用。输出分类和关联预览，标明依据；未知项进入待核对清单。
2. 在隔离副本备份并迁移，新增字段/关联不改变原任务身份、状态、标准版本、成果及验收历史。下一 schema 编号根据实施时最新版本确定。
3. 分类依据任务交付目标，编号只作线索。需要更正分类时保留旧值、理由和操作者；不得自动给未明确分类的任务设置科研归属。
4. 从现有总体设计及任务登记科研节点、主归属和引用；没有对应任务的方向保留为空。保留原阶段与里程碑，禁止用节点父子关系替换执行依赖。
5. 原 `focus_task_id` 保留到对应类别焦点；无法判定类别时保留原值并提示核对，不静默清空。文档关联复用既有索引；主计划及核对版本显式登记。
6. 同一输入重复处理不重复创建对象。验证失败回滚整次关联发布；已生成的备份与核查报告保留。历史文档与管理库有差异时分别展示来源，由记录化处置解决。

## 4. 任务与计划交接规则

从「下一步工作」的任务节点直接打开该任务登记的主计划章节。任务 ID、类别、状态与依赖来自同一项目的管理记录，计划正文以仓库中的 Markdown 为准。参考计划在任务详情中查看。复用现有文档入口，按需补足章节定位。

列表与计划入口复用既有检查。无主计划时显示待关联。文件缺失、章节失效或歧义时保留引用和核对历史，并显示原因。文件变化或尚未核对时提示待核对，明确区分当前文档和上次核对版本。打开计划时按实际文件复查引用，浏览操作只读。改类后仍留在旧分类的人工安排标记待复核，保留主计划及返回原分类的入口。[已验收入口与字段](wb15_05_acceptance.md#wb-16-可复用入口与待复核项)

前置依赖未满足或验收证据失效时显示具体原因，人工置顶仍显示阻塞。`in_review` 指向现有验收入口，`done` 和 `cancelled` 归入历史，`blocked` 展示阻塞与恢复信息。任务状态流转继续由现有服务管理。执行需要 Codex 时，在会话中根据任务和项目文档组织指令。

## 5. 验收矩阵

| 场景 | 预期结果 | 验收依据 |
|---|---|---|
| 同时登记科研任务和 WB 任务 | 科研路线无 WB 节点；维护视图只展示 WB；全部视图分开计数 | 共用查询验证与页面记录 |
| 工作台训练入口依赖科研接口交付 | 依赖可跨类别追溯，科研路线不因此新增 WB 分支，WB 完成不改变科研状态 | 依赖与状态验证 |
| 旧任务分类未知或焦点待核对 | 保留原数据并提示，不误计完成数、不丢失原焦点 | 迁移前后对象核对 |
| 历史 WB 交付尚未登记管理库 | 展示原交付依据和“待补登记”，不归零进度；原剩余范围及新增范围单列 | 维护视图与历史文档对照 |
| 一个科研任务引用多个路线节点 | 只设一个主归属，汇总按 ID 去重；父子环与非法类别挂载被拒绝 | 关系约束验证 |
| 空分支、未拆分方向、仅含已取消任务 | 均不显示研究方向已完成 | 汇总规则验证 |
| 路线图逐层展开、缩放、平移与互定位 | 节点可读，详情/展开操作明确，回到任务仍保留类别 | 实际浏览器记录 |
| 科研与工作台建设的近期任务已关联主计划 | 从任务节点直接打开登记的项目 Markdown 章节，任务身份及类别可核对 | Web 集成与实际浏览器验证 |
| 人工置顶任务存在未完成依赖 | 保留近期安排，显示具体阻塞原因及依赖入口 | 服务与页面验证 |
| 无主计划、文件丢失、章节更名或歧义、内容变化 | 显示具体原因，保留引用与旧核对记录；修正引用或重新核对后恢复正常展示 | 临时文档场景验证 |
| 计划在列表加载后、打开前变化 | 打开时再次检查当前文件，明确显示待核对或章节失效，保留上次核对信息 | 计划入口集成与浏览器验证 |
| 已验收证据失效 | 历史验收保留，显示待复核，阻止下游误判就绪 | 证据与依赖回归 |
| 两个标签页编辑同一关联 | 过期修订被拒绝，重复请求不重复登记，活动与数据同事务保存 | 冲突与事务验证 |
| 原任务、成果、决策、文档、预测入口访问 | 旧 URL 及原验收、预测流程继续可用 | 相关既有回归及浏览器检查 |
| 升级、重复升级、备份恢复或失败回滚 | 原对象身份及关联可核对，失败不留下部分分类/节点/计划关系 | 隔离副本迁移与恢复记录 |
| 科研数据和产物隔离 | 本轮流程前后领域库、原始数据、模型和特征产物内容不变，科研任务状态及验收记录不变 | 文件哈希与管理记录对照 |

实现后运行相关 pytest、Ruff 检查及格式检查。浏览器至少覆盖 1366×768、1920×1080，以及窄屏下任务和计划入口；包含空数据、错误提示和跨类别导航。各项验证记录实际环境与结果，未执行项明确列出，不以文档描述替代验证。

## 6. 交付收口

每个工作包交付后登记实际代码/配置版本、迁移版本、测试及浏览器证据、限制和恢复方式，形成对应 WB 交付记录。通过现有验收服务完成 WB 任务，不代替科研任务验收。

交付汇总分开回答“新增了哪些工作台能力”和“初始化了哪些科研结构引用”。科研执行、模型训练、领域数据发布及 WB-07/11/12 的后续接入继续按其各自计划开展，不纳入本轮收口条件。
