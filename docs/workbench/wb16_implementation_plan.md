# WB-16 页面整合与维护入口实施方案

2026-11-20（Asia/Shanghai）。WB-14 和 WB-15 已正式验收。WB-16 将项目总览、分类导航、任务、文档与成果串起来，并提供独立的工作台维护入口。[主方案第 3.2 节](../architecture/project_workbench_plan.md#32-页面职责与默认范围) · [统一排期](management_improvement_plan.md#0-统一执行顺序与当前下一步) · [WB-15 交接](wb15_05_acceptance.md#wb-16-可复用入口与待复核项)

## 1. 目标与交付范围

项目总览默认呈现科研状态，工作台建设单列摘要。科研用户能从焦点、路线摘要、近期工作进入已登记任务与计划章节。工作台维护用户能集中查看建设任务、执行计划、验收证据、历史交付及剩余范围，并进入既有备份恢复流程。

复用 schema 8、四组导航、WB-13 分类查询、WB-14 科研路线和 WB-15 近期任务与计划预览。任务、文档和成果的列表使用同一分类规则。已有详情、固定版本、验收动作和深链接继续可用。WB-17 承接跨工作包整体验收，科研任务、训练接入及领域工作继续按原专项排期推进。

## 2. 开工基线与使用口径

### 正式数据基线

- 按 `configs/workbench.yaml` 只读核对 `cat-ai`。管理库为 schema 8，`quick_check=ok`，外键检查无错误。WB-13、WB-14、WB-15 均为 `done`，WB-14 和 WB-15 的父任务验收记录分别是 `54` 和 `70`。任务表中尚无 WB-16 前缀，开工登记前再核对一次。
- 科研 12 项、工作台建设 22 项，当前均为 `done` 且现有验收证据无待复核标记。两类均无活动近期任务和焦点，待分类任务为 0。十项历史科研任务仍无活动主计划。正式数据适合验证历史和空态，活动任务、阻塞及证据失效用隔离样本覆盖。
- 文档索引有 22 项文档，其中 4 项有活动用途登记，分别为 1 项科研执行计划、3 项工作台执行计划。12 条活动历史建设交付均未链接到正式任务，来源状态均为 `changed`。维护页需同时保留原交付描述、剩余范围、待补登记和来源复核提示。
- 管理库一致性副本上，总览、旧任务列表及阶段筛选、文档、成果、决策、路线、两类近期任务、数据基础、预测和共用查询共 12 个入口均返回 200。当前总览使用项目级任务和固定里程碑清单，任务列表尚无分类筛选，文档和成果为项目级列表，独立维护入口尚未接入。代码基准为 `db4ea20` 加工作区改动，正式交付以实际文件版本清单为准。

### 分类与版本规则

| 对象 | 分类与展示口径 |
|---|---|
| 任务、焦点和近期安排 | 任务类别以正式登记为准，筛选值复用 `research`、`workbench`、`all`、`unclassified`。空类别列为待核对。旧分类保留的人工安排沿用 WB-15 的复核提示，仍可打开该任务的计划。前置链接允许跨类别，显示目标类别。 |
| 统计 | 按项目、类别和任务 ID 计数。取消单列，工作台和科研的有效完成分别计算。`done` 但证据待复核时保留原状态，单列复核数量。全部范围显示分类小计。状态计数与路线纳入范围、科研证据分类、样本计数分别说明分母、来源及观察时间。 |
| 文档 | 从活动的用途登记及同项目的活动计划引用读取用途与适用类别。科研文档入口同时呈现有明确科研适用依据的系统文档。多项依据明确覆盖两类时，同一文档可进入两类列表，在全部范围按 ID 去重。依据不足或用途存在待复核差异时列明原依据，可从全部或待核对范围查阅。复用现有用途值，文档路径和编号可用于查找。 |
| 成果与验收 | 以任务验收记录和其他已登记的明确任务关联确定适用范围，证据以同项目的 ID 和固定版本配对。跨类别共用同一对象，全部范围按成果 ID 去重，历史核对继续显示各自固定版本。未建立可靠关联的项目级成果留在全部或待核对清单。 |
| 历史建设交付 | 按 `workbench_delivery` 的原 WB ID、交付范围、剩余范围、来源及检测状态展示。仅通过已登记的 `task_id` 互定位，未补登时显示历史来源和待补登记。来源变化时保留原章节、固定哈希和交付结论。 |

### WB-16-01 开工基线与分类契约

以正式配置复核编号、版本、任务、已核对主计划及文档用途、证据和历史来源。记录现有路由的缺省范围与查询参数。对照 `queries.query`、`roadmap.snapshot`、计划服务、任务验收及成果索引，定义首页和列表的共用查询字段。隔离样本覆盖两类活动任务、项目空库、待分类、跨类共用文档和证据、历史已关联或待补登、来源变化和固定证据失效。

### WB-16-02 项目总览与分类导航

已有 `/` 聚合科研焦点、A–F 路线简要摘要、近期与最近完成、问题和有效成果入口。路线摘要复用 WB-14 的纳入与去重口径，近期工作复用 WB-15。建设摘要独立进入维护页。项目级活动、问题或资产缺少分类关联时展示明确的项目级范围。可独立核对的样本记录数和材料数分别展示，未接入的数据源和查询成功的空结果分别标明。

保留四组导航，在项目管理组提供「工作台维护」。科研工作入口显式带 `category=research`，维护入口带到建设范围。列表的分类、关键筛选和返回路径以 URL 恢复，允许刷新、分享及浏览器返回。跨类别跳转标明目标类别。

### WB-16-03 任务文档与成果筛选

在 `/tasks`、`/documents` 和 `/artifacts` 接入共用分类规则。保留无 `category` 时原有项目级列表和任务的 `q`、`stage`、`status` 行为，新增导航链接显式指定范围。允许的类别值与共用查询一致，非法值明确报错。筛选先于排序与分页，总数与列表口径一致。

任务与关联问题、决策沿用同一对象，可从科研或建设上下文进入。文档显示已登记用途、适用类别、关联任务和计划章节入口。成果显示交付范围、固定版本与证据有效性。保留 `/tasks/{task_id}`、`/roadmap` 深链和 `/artifacts/{artifact_id}?version=…` 等既有地址，以及 WB-15 的任务计划预览参数和章节锚点。

### WB-16-04 独立工作台维护入口

新增 `/workbench-maintenance`，集中展示建设待办与阻塞、建设方案与执行计划、最近验收和固定证据、历史交付与剩余范围。统计读取工作台类别。计划、任务、证据、备份及恢复操作通过现有页面与服务打开。历史记录和正式任务分别展示，已明确关联的提供双向入口，避免按编号前缀推断关系。

逐条整理 12 条来源变化记录，列出原登记版本、当前来源、章节和复核结果。能从已有备份找到固定版本时对照交付及剩余范围。需要改动的登记按已有服务保留原版本、理由和操作者，证据不足的保留待复核。

### WB-16-05 跨页面联调与兼容回归

在隔离库分别走通「科研总览 → 分类任务 → 计划预览或科研路线 → 返回」和「维护 → 建设待办或历史交付 → 计划与验收证据 → 返回」。检查刷新、浏览器返回、清除筛选、参数组合、空态和过期入口。在实际数据副本对照聚合、历史与空态，验证浏览前后数据一致。旧任务动作、成果、决策、文档、预测和备份入口执行回归。

### WB-16-06 专项验收与交付

按下述矩阵记录实际代码、配置、文档及证据版本。在隔离副本演练部署、备份和恢复，核对旧任务、验收、科研领域库及产物。通过后按现有服务正式交付，记录子任务及父任务的验收证据。整理 WB-17 可直接复跑的入口、样本、恢复证据及待复核清单。

## 4. 实施与登记安排

1. 执行从 WB-16-01 开始。父任务 `WB-16` 的主计划登记到「1. 目标与交付范围」，各子任务分别登记到第 3 节对应标题。正式任务使用 `workbench` 类别，按表登记真实前置、交付物、验收项及发生时间。父任务以前置 `WB-16-06` 为收口门槛，分别引用六项子任务证据。
2. WB-16-02 和 WB-16-03 共用已核对的数据契约，默认先接总览导航，再接分类筛选。两项交付后进入维护视图，随后完成联调和专项验收。独立的开发分支可并行验证，正式验收仍按前置关系推进。
3. 联调以真实库一致性副本验证已登记状态，以独立文档和样本任务覆盖异常。浏览数据和关联修订分别核对。若发现旧来源或归类缺口，记录同项目证据和处理结果。
4. 发布前保存正式管理库与引用文件的一致性备份，完成恢复与隔离部署演练。正式交付后再核对端点、证据和库完整性。代码回退前保留当前活动库及发布后写入，业务回退使用可追溯修订。

## 5. 专项验收矩阵

| 场景 | 通过条件 | 验证方式 |
|---|---|---|
| 首页默认、分类与统计 | 科研焦点和近期入口正确。建设摘要独立。实际库、空库、待分类、取消和证据失效的数量可按 ID 和有效范围对照。 | 服务与 Web 集成测试、正式库副本 |
| 分类导航与筛选 | 两类、全部和待核对范围可用。参数组合、清除、刷新、返回与跨类别提示一致。检索和分页在同一范围。 | Web 集成测试、Edge |
| 文档、成果和验收 | 跨类共用项可追溯且在全部范围去重。无依据、旧版本、证据失效和任务/文档错配能区分，旧预览和章节链接可用。 | 隔离样本、Web 集成测试、Edge |
| 工作台维护与历史 | 只展示建设范围，历史交付、剩余范围、待补登记和来源变化分别可查，备份恢复入口可达。 | 实际历史记录对照、Edge |
| 旧入口和隔离 | 旧 URL、任务动作、决策、文档、预测和证据预览通过回归，浏览前后逐表一致，科研状态、验收和产物核对通过。 | 全量 pytest、Ruff 检查及格式检查、数据与文件对照 |
| 发布恢复 | 发布前、隔离验收后和正式验收后的备份可恢复，关键任务、关联、固定证据、历史来源与发布版本可查。 | 管理库一致性包、恢复记录、正式服务冒烟 |

Edge 覆盖 1366×768、1920×1080、390×844，检查键盘操作、窄屏筛选和关键往返。验收记录注明实测环境、命令、证据路径和待办项。
