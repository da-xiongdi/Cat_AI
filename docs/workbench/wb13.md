## 部署和回退

本次使用 [WB-13 收口脚本](../../scripts/close_wb13.py)；默认在活动库快照上演练，`--apply` 先通过同样的演练，再对正式库执行。脚本遇到已登记的 WB-13 编号会停在预检。若登记事务已提交而验收尚未提交，应核对当次 `before.sqlite`、`deployed.sqlite`、在库修订和证据，从当前状态用正常验收服务续办。

1. 部署前固定并审查实际代码及配置版本，重新检查活动库 schema、任务 ID 占用、任务与上下文修订、来源章节和哈希；对冲突重新预览，不能套用旧预览。复核并行科研工作，按正常服务登记任务和验收，不能直接写库伪造状态。
2. 协调停止写入或使用一致性备份，同时保存当前来源文件、哈希及缺失清单；在隔离副本先演练迁移、分类及恢复并核对受影响任务、标准、review、证据、固定成果和新增关联。02–04 已有正式写入，不重复盲目应用；05–07 的实际服务和数据应按现场版本确认。
3. 部署时使用当前代码与 schema 8，按服务的预期修订和幂等请求实施；检查完整性、外键、查询及旧接口。新 schema 库不得直接交旧代码打开。
4. 回退先停止写入，用 `backup.backup_database` 与 `backup.create_bundle` 将当时的活动库与索引文件导出到新目录，按部署包的来源清单补存非索引来源。用 `backup.preview_bundle` 和 `backup.restore_bundle` 在新目录试恢复部署前包。将最新导出与 `before.sqlite`、`after.sqlite` 按主键和修订比较，保留部署后增加的分类、历史、节点、计划、上下文和关联，以及同期科研任务、验收、成果和预测记录。核对并合并业务变化后再决定是否切换。无法安全合并时保留当前库；禁止用旧备份直接覆盖活动库。
