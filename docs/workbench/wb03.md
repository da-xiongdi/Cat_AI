# WB-03 成果与来源索引

本阶段提供 Python 索引服务，读取显式登记的文件，不扫描整个工作区、不修改源文件和领域库。工作台管理库 schema 从 1 升到 2；运行 `migrate` 时会先为已有旧库创建 SQLite 备份（例如 `workbench.sqlite.v1.backup`），同名备份已存在时停止。请另行备份被引用的原文件；管理库不是成果文件的备份。

## 使用

```python
from pathlib import Path
from catalyst_ai.storage.workbench import migrate
from catalyst_ai.workbench import index, service

root = Path.cwd()
db = Path("data/workbench.sqlite")
migrate(db)
service.create_project(db, "cat-ai", "Cat AI", request_id="project-1", actor="操作者")
index.configure_workspace(db, "cat-ai", root, request_id="workspace-1", actor="操作者")
index.register(db, "cat-ai", "s1b-selection", "selection",
    "artifacts/reports/s1-b-20261113-v4/selection.json",
    request_id="register-selection", actor="操作者")
index.register(db, "cat-ai", "s1b-features", "features",
    "artifacts/reports/s1-b-20261113-v4/features.json",
    request_id="register-features", actor="操作者")
scan_id = index.scan(db, "cat-ai")
print(index.get_scan(db, scan_id))
artifact = index.get_artifact(db, "s1b-features")
revision = artifact["revisions"][0]["file_sha256"]
print(index.preview(db, "s1b-features", revision, offset=0, limit=20))
```

已有 WB-02 项目只需迁移、配置工作区并登记来源，不要重复创建项目。按需注册 `snapshot`、`qualification`、`split`、S1-B `selection`、S1-B `features`、R1 比较 `report`、R1 预测包 `model`（登记 `manifest.json`）、`document` 或 `attachment`。单个逻辑 ID 可登记多个位置；ID 在整个管理库中唯一。注册路径相对已配置工作区，拒绝绝对路径、向上遍历以及解析后逃逸工作区的符号链接或目录联接。工作区根目录配置后不可直接更换。

## 身份、校验及观察

每个文件修订以文件 SHA-256 固定，另保存内容 ID、规范化内容 SHA-256 及有界摘要。快照、资格、划分和 S1-B 选择/特征按各自内容 ID 和 `content_sha256` 规则验证；R1 报告验证去除自身摘要字段的规范化摘要；R1 模型清单验证 `model_id` 和同目录 `model.pkl` 哈希，不执行反序列化。普通文档/附件的内容 ID 由类型和文件哈希组成。扫描会对已登记的快照、资格、划分、S1-B selection/features 的引用进行索引内查找；引用未登记或未成功检测时，观察记录的 `error` 中给出 `unresolved indexed references`，这不是对未登记来源不存在的断言。报告的科研范围、模型有效性和跨运行配对条件仍须依据原报告人工判断。

`scan` 对登记范围逐文件读取（默认单文件上限 64 MiB，可通过 `max_bytes` 调整），记录 available、missing、invalid、read_error 及异常；文件过大记为 invalid。检查结果完成后在一个事务内发布新代次，并同步 WB-02 证据状态。旧修订继续存在：相同修订仍有任一可用位置即为 available，否则按观察结果标记 changed、missing、invalid 或 read_error；历史验收不被覆盖。若内容变更且其他位置仍保存旧内容，旧修订继续可用。检测状态是指定时间的观察，文件随时可能在扫描之后变化。

意外中断不会发布半代索引，上一完整代次继续可用；重启后可用 `get_scan` 检查未完成扫描并在确认其已停止后调用 `interrupt_scan`，再发起新扫描。并发扫描或注册改变范围时，后发布者检测到基线变化会失败并保留原已发布代次。单文件失败是可发布的明确观察，不推断其他文件缺失。`get_artifact` 保留路径、各代修订、当前检测状态和当前代次观察；`list_artifacts` 和 `preview` 支持分页。预览读取前重新校验文件及模型包，变化时要求刷新索引；文档返回纯文本，界面层须自行转义和安全渲染。预览不加载模型序列化文件。大 JSON 目前在大小上限内整体解析后分页，并非流式解析。

`adapters.verify_feature_catalog(database, selection_path, features_path)` 使用 SQLite `mode=ro` 与 `query_only` 核对 S1-B 构建、绑定和逐值索引，不调用会写库的 `get_build()`。该核对按需执行，不自动触发；索引本身不验证数据库与文件跨介质的一致快照。

本阶段不提供 Web 页面、训练执行、目录自动发现或实际项目导入。若后续修改或移动管理库、恢复备份，需重新配置可用来源并刷新索引；以固定版本关联验收时使用 `artifact_id` 和对应 `file_sha256`。源文件及 Git 未提交内容仍需单独备份。
