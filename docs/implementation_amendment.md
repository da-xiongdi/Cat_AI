## 2. 按顺序交付的小切片

### I1：目标资格视图与覆盖清单（已实现，软件已验证）

目标：在不修改原始事实和既有严格快照语义的前提下，明确哪些记录能服务于某一个训练目标。

- 输入：显式选择的记录清单、目标名称/定义/单位、规则版本和数据类别；不默认把整库视为训练集。
- 输出：资格清单，保存全部输入ID及内容哈希、纳入/排除结果、原因码、规则版本、数据类别，以及来源/配方/批次覆盖计数。哈希是内容身份，不能只保存会变动的数据库查询条件。
- 标签缺失、口径不符和未核验分别记录原因；一个目标不可用不删除事实，也不禁止该记录用于其他合格目标。未知单位不猜测换算，目标不填均值。
- 样本粒度以 observation_id 为基础，关联 record/source/recipe/synthesis/test；同一test的多个时间点或重复观测不能静默覆盖或无规则求均值。目标对应多条观测时显式列出，无法确定上下文时拒绝生成训练行。
- 兼容路径：先显式筛选，再把合格record_ids交给既有 build_verified_snapshot 复核并冻结；保存资格清单与snapshot_id的关联。某条记录内若存在同目标但不合格的其他观测，当前快照仍拒绝整条，不通过静默删观测绕过；逐观测冻结需另设版本化接口与测试。
- 审核撤销、原件缺失、内容哈希变化等完整性问题在最终冻结时阻断，不能作为普通缺标签排除而掩盖。既有 dataset build 无显式ID时的严格行为保持不变。

实际落点：datasets/eligibility.py、dataset qualify CLI、快照旁qualifications关联清单，复用storage/snapshots.py；具体行为见[接口契约](api_contracts.md)。规则版本1以不同有效time_on_stream区分多观测，其他重复样上下文暂不支持。

验收：混合目标/缺标签输入有完整原因记录；无标签不造值；多观测不丢失；未审核及篡改不能绕过门禁；同样输入和规则得到同样清单内容。空合格集输出原因并停止后续训练。

### I2：分组清单与集合交叉检查

- 输入：已冻结的数据、I1样本清单、明确的泛化问题、分组策略、seed及划分比例；保存split_id和每个样本的实际归属，不只保存随机种子。
- 分别定义 source/paper、recipe、synthesis 评估；按论文评估与按配方评估分别报告，材料家族留出在覆盖允许时增加，random仅作对照。
- 先归并已确认的论文别名和重复来源；对所选策略必须隔离的实体及已确认重复关系建立泄漏关联组，整组分配。分别用source_id和recipe_id拼成元组，不能保证其中任意一项不跨集合。
- 组成相同本身不等于重复实验，不能仅凭组成签名认定记录同一；未知归并关系记录为限制。跨集合交叉报告区分违反所选策略的阻断项与其他关系的提示项。
- 报告样本数、独立论文/配方/批次数及材料/工况覆盖。独立组不足或关联组合并后无法切分时给出原因，禁止回退随机切分并宣称通过分组验证。

拟落点：datasets 的split清单与验证；不改实体存储结构。

验收：同组及已确认重复观测不得跨集合；划分可重现；别名和交叉关系有专门负例；不足以切分时明确失败/跳过。

### I3：组成编码与设计输入边界

- 设计输入通过受限对象/字段白名单构建，只包含设计前可知组成、计划合成步骤和指定测试工况；观测目标、制备后表征及携带结果的provenance文本不能进入设计特征。诊断模型另行准入表征。
- 对历史记录，区分实际合成信息与候选的计划参数；无法确认设计时可获得的字段不直接准入。测试时间等字段按任务含义明确其可用阶段。
- composition_signature 按明确计量基准、组成范围、物种、角色及数量生成；只消除排列差异，不自动归一化未知组成、不合并不同合成路径，也不替代recipe_id或synthesis_id。
- 保存特征版本、字段来源、可获得阶段和缺失状态。先做简单组成/工艺/工况特征，再以分组验证收益决定是否引入Magpie等描述符。

拟落点：features 与受限输入契约，逐步落实 interfaces.py 的现有约定。

验收：调换组分顺序不改变组成特征；改变实测目标/BET不改变设计特征；改变合成计划能在相关特征中体现；未知计量基准明确报缺失/不可用。

### I4：一个目标的可复现基线

- 按真实覆盖选择目标，先比较Dummy、Ridge和一个树模型；使用同一资格规则与划分，模型选择不使用测试集结果。
- 固定单位换算和固定元素属性可在切分前计算；数据学习的填补、编码词表、缩放、特征选择及任何目标编码仅在各训练折fit。调参如引入，只用训练侧的分组验证，测试集最终评估。
- 运行清单关联资格清单、snapshot_id、split_id、特征版本、配置/代码/依赖证据、seed、模型文件及评价报告。
- 报告MAE/RMSE/R²、基线对照、独立组数、目标与工况覆盖；R²在样本或目标方差不足时注明不可计算。暂不承诺达到论文的指标。

拟落点：modeling 最小训练管线及运行报告；按实际需要添加依赖并更新锁文件。

验收：利用不同训练/验证分布检测全表拟合；验证集独有类别不会进入训练词表；测试数据不参与拟合/选模；相同冻结输入、环境及seed在规定容差内可复现。

### I5：按原D/E/F阶段引入研究方法

基线与分组评价完成后再增加SHAP、适用域和经验不确定性；SHAP用于提出假设，区间覆盖率需独立验证。随后才将满足约束的候选纳入实验计划。超参数调参与候选实验设计分开；响应面不直接作为推荐结果。活化能拟合与独立论文复现后置，不构成当前验收要求。

## 3. 真实数据与工程验证并行

真实数据工作沿原B任务开展：选少量有授权、可定位的文献/内部记录，明确指标和单位，逐项核验，统计覆盖后再选训练目标；软件不代替研究者声明人工核验，也不自动联系论文作者。

I1–I4的工程边界可以先用隔离的synthetic_demo fixtures验证。未来若增加训练演示路径，必须显式开启，产物保留scientific_use=false并与研究结果隔离；这不等于当前已提供该功能。真实数据不足时只交付软件验证及不足原因，不以模拟指标替代科研效果，不为凑样本放松分组。

## 4. 每次任务的交付约定

1. 开工先读取开发指引、本清单和progress，核对当前实现，仅选择一个切片作为本次范围；有依赖的后续任务不一并铺开。
2. 把所选切片写成“输入、输出、准入规则、失败行为、验收证据”；涉及已有接口的行为变化先在契约中明确，保留现有门禁回归。
3. 完成功能后运行相关边界测试和必要的集成/CLI检查；涉及Python变更时执行pytest及ruff。只改文档时核对链接和基准文档完整性，无需将历史测试结果写成新验收。
4. 更新progress中的“规划/已实现/已验证”，附实际命令、结果、变更文件和限制；软件验证与真实数据/科研验证分别记录。架构取舍记入decisions，接口变更记入api_contracts。
