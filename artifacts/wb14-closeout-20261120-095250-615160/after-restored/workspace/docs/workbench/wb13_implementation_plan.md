# WB-13 管理分类与关联基础：任务分解

日期为 2026-11-18（Asia/Shanghai）。正式登记、部署和父任务验收结果以[交付记录](wb13.md)及工作台的验收记录为准。

依据：[工作台建设方案](../architecture/project_workbench_plan.md)、[统一执行顺序](management_improvement_plan.md#0-统一执行顺序与当前下一步)。WB-13 对应原 WP1，以下子任务统一使用 WB-13-01～WB-13-08，不另建 WP 待办。负责人及完成日期在实际排期时填写，不推测工期。

## 1. 目标、基线与边界

WB-13 交付供 WB-14～WB-16 复用的管理数据与服务基础：两类任务可区分，历史建设进度可承接，路线层级与任务可关联，执行计划有版本引用，焦点与近期安排按类别保存，各页面使用同一查询口径。

实施前的只读基线为 schema 7，已有任务服务、固定成果索引、研究分类、模型运行及预测队列。WB-13-02～04 将正式库升级到 schema 8，并登记 12 条历史 WB 引用、14 个科研节点及 8 条任务关联。[基线与契约](wb13_01_baseline_contract.md) · [专项验收与部署记录](wb13.md)

本任务沿用现有存储、任务状态机、验收、修订号、请求幂等及活动日志。新增对象采用稳定 ID、项目隔离与事务一致性，不复制任务正文、计划正文或成果文件。

| 属于 WB-13 | 后续任务负责 |
|---|---|
| 分类与关联持久化、服务、校验及共用查询 | WB-14：路线图画布、展开/折叠及互定位界面 |
| 计划引用、章节/文件检测与核对记录 | WB-15：近期工作页面、完整执行就绪编排、Markdown 交互及 Codex 指令生成 |
| 分类焦点、近期安排及文档用途元数据 | WB-16：总览、导航、维护入口与分类表单 |
| 本次迁移、服务与旧功能的专项回归及恢复验证 | WB-17：跨页面整体验收、完整浏览器主流程及本轮收口 |

不实施 WB-07/11/12，不训练模型、不执行科研任务、不修改领域数据库、模型或特征产物。科研任务继续独立推进，S2/S3 状态不因本次建设改变。

## 3. 分任务实施与验收

### WB-13-01：基线盘点与数据契约

实施内容：

1. 只读检查实际 schema、任务及依赖、固定验收、焦点、文档索引、历史 WB 交付及当前未提交修改；保存观察时间和目标文件版本。
2. 区分已有服务、缺口、原规划剩余项与正在进行的其他工作。历史交付按实际范围承接，不能将“有入口”当作整项完成。
3. 确定下表逻辑对象的物理落点、唯一约束、修订规则、备份包含范围和回填方法。字段名为拟议契约，编码时需在本计划或契约文档固定最终名称。
4. 明确旧调用的默认行为与新查询的类别参数；建立迁移前后任务、验收、成果及领域保护对象的对照方法。

| 逻辑对象 | 最小约定 |
|---|---|
| 任务类别 | `research` / `workbench`；历史未知允许空值并显式待核对；不是新增任务状态 |
| 历史交付引用 | 原 WB ID、已交付范围、剩余范围、来源章节/固定版本、原交付日期、本次登记时间、可选正式任务关联 |
| 科研路线节点 | ID、项目、阶段、父节点、排序、来源版本；任务与节点的主归属/引用单独保存 |
| 任务计划引用 | 任务、文档、相对路径、章节、用途、主计划标志、已核对哈希、核对人/时间和修订 |
| 分类工作上下文 | 项目与类别唯一焦点、近期任务引用/人工顺序、修订；不复制任务状态 |
| 文档用途 | 建设方案、科研方案、执行计划、验收等用途及适用类别；复用 document 索引 |

验收：交付基线报告与最终契约；每个新增对象有身份、所属项目、修改接口、历史保留及错误处理规则。确认原状态机、阶段标签与里程碑含义不变。此项不以新增数据库表或科研进展作为完成条件。

### WB-13-02：增量迁移与任务分类

实施内容：扩展 `src/catalyst_ai/storage/workbench.py` 及管理服务，采用下一可用 schema 版本；复用 SQLite 备份接口与现有事务。分类必须基于交付目标，不能按编号前缀无条件回填。WB 任务允许没有科研阶段；已有科研阶段和里程碑不重排。旧创建入口未传类别时保留为待核对，不因缺少新字段破坏原调用。

分类回填提供预览、依据、冲突、预期修订及应用结果；未知项保留。分类修订记录旧值、新值、理由和操作者，不以状态重开模拟分类修正。不得直接编辑已完成任务的目标、检查项或原验收。

验收：schema 7 副本升级及重复升级可核对；任务 ID、status、criteria_version、旧修订/验收和固定成果引用不被迁移覆盖；回填重复应用无额外业务修订，过期修订及跨项目写入被拒绝。测试失败回滚到一致状态，已有同名备份不被覆盖。

### WB-13-03：历史建设交付承接

实施内容：引用 WB-01～WB-12 原交付与规划来源，分开记录已交付范围、剩余范围和管理库登记情况。历史交付引用是证据元数据，不另造一套任务执行状态。

当前重点：WB-02～06、WB-08/09 已有交付；WB-10 承接模型证据台账范围；WB-07/11/12 继续保留未交付范围。WB-01 草案和 WB-05 实际导入相互关联，不重复导入首批项目。具体状态以原来源及后续修订为准，不将本段硬编码为永久常量。

未有正式任务的历史交付允许先登记来源引用并显示“历史已有交付，待补登记”，不创建一批 planned 任务来代表已完成工作。后续建立正式任务或补做当前复核时，记录实际发生时间和依据，不伪造原日期的状态流转、操作者或验收。

验收：重复承接不重复创建对象；失效来源保留原记录并显示待复核；历史交付与当前任务相互可追溯。WB-07/11/12 不因批量整理变为 done，WB-10 不被扩大为全部训练能力已完成，科研任务的执行状态与验收不变。

### WB-13-04：科研节点与任务关联

实施内容：基于现有总体设计与任务登记 A–F 节点、来源章节及分支，支持创建/调整/查询节点和任务关联。一个任务最多一个主节点，可有多个引用节点；未确定主归属时显示待关联。WB 建设任务不挂入科研节点；未知类别先核对后关联。

验收：拒绝自父节点、父子环、跨项目节点或任务引用、重复主归属和非法阶段关系；节点调整沿用修订/活动规则。父子关系不生成执行依赖；跨节点汇总按任务 ID 去重，空分支不宣称完成。此项只提供关系与查询，不交付画布或完整路线状态展示。

### WB-13-05：执行计划与文档引用

实施内容：复用 `workbench/index.py` 的文档及固定版本，增加用途分类与任务计划关系；任务可有多份参考方案，但最多一份有效主执行计划。保存项目相对路径、可解析章节定位和已核对文件 SHA-256；核对记录追加保留。

提供引用检测与显式重新核对服务。当前文件检测结果与“上次已核对版本”分开保存；内容变化不自动更新已核对哈希，缺失章节不静默跳转其他同名标题。文档路径解析、符号链接/目录联接和允许根目录检查复用现有边界。

验收：覆盖多计划、主计划冲突、跨项目引用、文件缺失、内容变化、章节更名/歧义、路径逃逸、并发核对和旧记录查询。检测时验证实际文件，不能仅信索引中旧的 available 标记。这里只返回引用检测结果，完整实施条件编排及指令生成由 WB-15 完成。

### WB-13-06：分类焦点与近期安排

实施内容：以项目和任务类别维护焦点与近期任务引用，保留人工排序；修改不复制或改变任务状态。没有人工顺序时，共用查询按现有优先级、日期及稳定 ID 提供确定排序，优先级沿用 `low/normal/high/urgent`。

迁移原 `project.focus_task_id` 到可确定类别；无法分类时保留原值并提示核对。旧焦点字段/入口与新分类焦点的读写对应规则须明确，不能同时维护两个相互覆盖的事实源。引用已完成、已取消或分类变化任务时保留安排历史，并提示移入历史或修正类别。

验收：科研与工作台焦点互不覆盖；不能把另一项目或另一类别任务置为当前类别焦点；重复安排去重，顺序稳定，冲突更新被拒绝。只交付保存与查询，不实现 WB-15 的自动就绪编排或近期工作页面。

### WB-13-07：共用查询与兼容接入

实施内容：形成供 Web 和 CLI 调用的统一任务类别查询、分类计数、历史建设交付查询、节点关联、主计划检测结果及分类焦点/近期安排查询。共享服务返回范围、观察时间、缺项和来源版本；Web 只按结果展示，不复制校验逻辑。

新管理查询显式支持科研、工作台、全部和待核对范围；未知类别单列。已有 `list_tasks` 等调用和旧 URL 保持原行为，新类别筛选采用可选参数或独立服务。需要新增 API 时沿用输入模型、404/409/422、修订号、幂等、来源与 CSRF 校验；不为交付本任务提前实现 WB-14～16 页面。

验收：同一项目/类别在任务查询、焦点、节点和计数中归属一致；全部视图分列类别、统计去重、不把父项加子项当作额外进度。旧任务编辑/验收、索引、文档、决策、预测及备份接口的相关回归通过；新字段不导致旧请求报错或覆盖既有关系。

### WB-13-08：专项验收与部署收口

实施内容：整合前七项证据，在隔离工作区验证迁移、分类回填、历史引用、关联服务、并发和备份恢复。补充实际部署与回退说明，记录代码/配置/schema 版本、测试结果、保护对象核对、限制及后续接口。

验收：第 4 节矩阵通过；恢复后新增对象和旧验收逐项可核对，计划与历史交付引用的源文件纳入备份或有明确可用备份位置，缺失必须报告。旧 schema 备份仍可在新代码下按既有恢复契约迁移；新版库不直接交给旧代码打开。

正式应用前再次核查活动库任务修订、计划版本和编号占用，先生成一致性备份并在副本演练，再实施受控部署。回退须说明迁移后新增写入的保留/导出方法，不得用旧备份覆盖期间其他科研任务更新。WB-13 父任务通过正常验收后，WB-14 才进入可开始；WB-15 的共用服务也可据此准备。
