## 服务与兼容规则

`category_context` 提供 `set_category_focus`、`save_recent_task`、`get_category_context` 和 `migrate_legacy_focus`。按项目和 `research` / `workbench` 隔离，使用原任务 ID；写入通过现有请求幂等、事务、修订和活动日志机制。首次设置焦点传预期修订 0；没有焦点的分类也可以用空焦点创建上下文，再登记近期任务。近期任务以引用及人工顺序保存；同一活动引用唯一，删除安排为停用并保留记录及修订。顺序相同时按任务 ID 排序；`default_order` 按 urgent、high、normal、low，计划日期（空值在后）及 ID 排序，不改变任务状态。

旧 `project.focus_task_id` 是旧入口显示的最近选择指针。分类入口在旧指针已承接时同步它；未知类别或尚未承接的旧值不被新分类操作覆盖。`legacy_needs_review` 表示无法分类，`legacy_needs_migration` 表示可分类但尚未承接或存在冲突。`migrate_legacy_focus` 使用预期上下文修订显式承接；已有不同焦点时返回冲突，须人工核对，不自动覆盖。旧入口选择分类任务时同步该分类焦点，切换前会承接尚无分类上下文的旧焦点；旧入口仍可选择或清除未知类别任务。焦点或近期引用的任务变为完成、取消或不同类别后，引用保留并通过 `needs_review` 提示；停用安排保留历史。
