# WB-14 科研路线图实施方案

2026-11-18（Asia/Shanghai）。实施方案已制定，WB-13 已完成正式部署和父任务验收。WB-14 从基线与页面数据契约开始。

依据为[主方案第 4.2 节](../architecture/project_workbench_plan.md#42-总体研发路线图)、[统一排期](management_improvement_plan.md#0-统一执行顺序与当前下一步)和[WB-13 收口记录](wb13.md)。路线图将 A–F 科研阶段、已登记研究分支和任务状态放在同一页，支持从路线定位任务、从任务回到路线，以及有记录的节点组织操作。

## 1. 开工条件与基线

- 开始 WB-14 前，只读核对实际代码、配置、库版本、WB-14 编号占用及节点来源。用最新管理库的一致性副本开展开发与验收。[WB-13 正式部署与验收](wb13.md)
- 2026-11-18 的只读基线为 schema 8，包含 A–F 的 6 个阶段根节点、8 个 S2/S3 分支和 8 条主归属关系。S1A-01、S1B-01 待关联，科研焦点为空。总体设计与 S2 实施计划各有 6 个节点提示来源变化。开工时按实际查询复核，保留已登记关系及原固定版本。
- 优先复用 `queries.query(..., scope="research")`、`research_nodes`、分类焦点和既有任务验收证据判断。WB-14 提供路线图与任务互定位，WB-15 负责近期工作与计划交接，WB-16 负责总览及跨页面整合，WB-17 负责本轮整体验收。[WB-13-07 共用查询](wb13_07_acceptance.md)

## 3. 页面数据与统计口径

1. 主干按照[总体设计第 5 节](../architecture/system_design.md#5-一条实施主线与三种编号)的 A–F 顺序显示。阶段根节点使用阶段名，普通分支使用登记的来源章节名，身份以节点 ID 为准。缺少根节点的阶段显示「尚未登记」，浏览页面本身不创建数据。节点面板显示名称、来源章节、固定哈希、当前来源检测结果、观察时间和关联任务。来源变化或缺失时仍显示已有结构和任务，保留原核对版本，提供复核提示。
2. 查询以项目和 `research` 类别为范围，共用节点、任务关联、任务状态与焦点快照。页面初始提供阶段根与一级分支、子分支提示和摘要，展开时按节点加载。树形列表、画布和节点面板消费同一份摘要。按任务 ID 计算一次状态与证据有效性，复用到各分支和全图，避免按节点逐条重复查询。
3. 层级显示父子关系，任务卡标明主归属或引用，执行依赖仍以原任务详情为准。每个节点按子树内的有效关联任务 ID 去重，全图再次对任务 ID 取并集。取消任务单列，排除在有效分母和完成数之外。待归属科研任务单列并可进入任务详情；类别待核对项从共用查询的 `unclassified` 范围读取，在独立清单提示。工作台建设任务不进入科研统计。
4. 摘要依次显示受阻、推进中、待验收、可开始或待规划，并附各状态数量、已验收有效数与已纳入有效任务数。使用现有验收及固定证据有效性判断统计已完成项。任务状态为 `done` 但证据待复核时，保留任务原状态并单列提示，不计入有效完成数。WB-13 查询中的 `done_count` 与 `complete` 仅反映任务状态，路线摘要需补足这一判断。
5. 无子分支且无任务时显示「尚未拆分」，只有取消任务时显示「仅含已取消任务」。子树存在未拆分方向、适用该阶段的待归属任务或待复核来源时显示「范围待补充」或对应复核提示。只有在纳入范围明确、至少有一项有效任务、范围内核对通过且有效任务全部验收、证据可用时，显示「已纳入范围完成」。图上数字只表示已纳入的管理任务。

## 4. 页面入口、定位与写入

- 建议使用 `/roadmap?node=<节点ID>&task=<任务ID>&view=tree` 作为可分享的选中位置，`view` 缺省使用画布并提供树形列表入口。节点分支查询按项目校验父节点并只返回直接子分支和必要摘要。页面使用现有中文模板与本地静态资源，接入现有内容安全策略。窄屏优先使用树形列表，保留定位、详情与编辑入口。
- 焦点定位读取 `research` 上下文的焦点与复核提示。无焦点显示未设置，有焦点但无有效主归属时指向待归属清单；已结束或变更类别的焦点显示待复核。任务详情默认回到其主归属，从引用节点进入且该关联仍有效时可返回原节点。无主归属时落到待归属清单，失效或不属于本项目的 ID 提示定位失败并保留总览入口。
- 展开、缩放、拖动画布、切换视图与恢复视图属于浏览操作。组织调整通过显式提交，发送预期修订号、请求 ID、操作者和原因，复用 `save_research_node`、`save_task_node_link` 和现有来源、CSRF 校验。保留 A–F 阶段根身份和顺序，分支统一按 `sort_order`、ID 稳定排序。停用前处理活动子节点和任务关联。移动已有主归属时优先更新原关联的目标节点；涉及多条记录的变更使用同一事务并保留各自修订。过期修订反馈冲突并提示重新读取。
- 新分支或来源修订保存前核对登记章节和当前哈希。核对失败时保留已有记录。待归属任务由操作者按方案和任务证据选择节点。提供来源定位、复核提示与原值展示，复用现有安全路径和文档入口。

## 5. 验收矩阵

| 场景 | 通过条件 | 验证方式 |
|---|---|---|
| 实际结构、空项目、多层分支 | A–F 顺序与已登记分支一致，缺项明确，深层可导航且只按需取分支。节点来源异常有提示。 | 服务或 Web 集成测试；实际库隔离副本对照 |
| 状态、去重与证据失效 | 一个任务在主节点及多个引用节点出现时，全图和任一汇总各只计一次。空分支、仅取消、未拆分、证据失效、来源待复核与有效完成均得到对应结果。 | 汇总专项测试；图、树和详情结果对照 |
| 路线画布、键盘和窄屏 | 逐级及全量收展、缩放、平移、全屏、适应屏幕和复位有效。键盘可进入节点、展开和打开任务，画布或脚本不可用时仍能使用树形列表。 | Edge 验证 1366×768、1920×1080、390×844 |
| 互定位与深链接 | 主归属、引用来源、深层刷新、浏览器返回、科研焦点、待归属及失效 ID 均有可用结果。旧 `/tasks/{id}` 正常。 | Web 集成测试及 Edge 浏览器路径 |
| 组织操作与并发 | 同阶段移动、排序、新增、停用和关联调整可追溯。环、跨项目、跨阶段非法父子、重复主归属、挂入 WB 任务及过期版本被拒绝。同请求重试无重复修订。 | 服务专项、双标签页及事务回滚测试 |
| 旧能力与科研数据隔离 | 任务、成果、决策、文档、预测及备份原有入口回归通过。隔离库的合法变更限于路线对象及配套活动、请求、修订，科研任务状态、验收证据、领域库及科研产物核对一致。 | pytest、Ruff 检查与格式检查、前后数据和文件核对 |

部署前保存管理库一致性备份与路线来源文件清单，在副本演练编辑、备份和恢复，核对主归属、引用、修订及旧任务验收。页面可随代码回退，已产生的节点调整保留可追溯历史。需要撤销业务调整时通过管理服务提交反向修订。交付记录逐项引用实际测试及浏览器证据，并注明正式库登记和验收时点。
